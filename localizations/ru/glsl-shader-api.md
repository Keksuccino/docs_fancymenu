# API шейдеров GLSL FancyMenu

В этом документе описывается GLSL-рантайм, используемый в FancyMenu для:

- фонового меню `GLSL`
- элемента `GLSL`
- декоративного оверлея `GLSL`

Здесь рассматриваются режимы компиляции, многопроходная маршрутизация, поддерживаемые uniform-переменные и практические шаблоны написания шейдеров.

## 1. Обзор рантайма

FancyMenu рендерит шейдеры с помощью внутреннего конвейера OpenGL (`#version 150`) и поддерживает:

- однопроходные шейдеры (только проход `Image`)
- многопроходные шейдеры (`Buffer A` / `B` / `C` / `D` + `Image`)
- точки входа в стиле Shadertoy (`mainImage`)
- прямые точки входа фрагментного шейдера (`main`)

Исходники шейдеров вводятся как встроенные текстовые поля:

- `Shader Source` (проход `Image`, обязателен для отображения)
- `Buffer A Source` (необязательно)
- `Buffer B Source` (необязательно)
- `Buffer C Source` (необязательно)
- `Buffer D Source` (необязательно)

Если исходник `Image` пуст, отрисовка завершится ошибкой "no source".

## 2. Режимы компиляции

FancyMenu поддерживает три режима компиляции:

- `Auto`
- `Direct Fragment`
- `Shadertoy`

### 2.1 Режим Shadertoy

Ожидаемая точка входа:

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord)
```

FancyMenu оборачивает её в `main()` и передаёт координаты локальной области:

```glsl
mainImage(fmColor_FancyMenu, gl_FragCoord.xy - fmAreaOffset);
```

Обёртка умножает альфа-канал вывода на `fmOpacity`.

### 2.2 Прямой режим

Ожидаемая точка входа:

```glsl
void main()
```

Поведение совместимости:

- пытается использовать совместимый вариант с `gl_FragColor`
- также пытается вариант без совместимости (для современных шейдеров с явным `out vec4`)

В прямом режиме `fmOpacity` не применяется к вашему выводу автоматически. При необходимости применяйте его вручную.

### 2.3 Режим Auto

Auto последовательно пробует совместимые варианты (Shadertoy/direct) и использует первый успешно скомпилированный.

## 3. Предобработка исходника и встроенные макросы

Перед компиляцией FancyMenu нормализует исходник:

- удаляет UTF-8 BOM
- преобразует CRLF/CR в LF
- удаляет строки `#version ...`
- удаляет строки `precision ...;`

Вставляемый в рантайме пролог включает:

- `#version 150`
- `in vec2 fmUv_FancyMenu` (UV полноэкранной области в `[0,1]`, начало координат снизу слева)
- `#define iGlobalTime iTime`
- `#define texture2D texture`
- `#define textureCube texture`

Примечание:

- Если в вашем исходнике уже объявлено известное имя uniform-переменной (например, `iTime`), FancyMenu не будет добавлять его повторно.
- При этом FancyMenu всё равно пытается передавать значения в это имя во время выполнения.
- `textureCube` здесь — только макро-алиас; `iChannel0..3` являются uniform-ами `sampler2D`.

## 4. Система проходов (Image + Buffer A-D)

В FancyMenu есть 5 слотов проходов:

- `Buffer A`
- `Buffer B`
- `Buffer C`
- `Buffer D`
- `Image` (финальный экранный проход)

Поведение:

- Буферные проходы выполняются только если их исходник не пуст.
- Проход `Image` должен присутствовать, чтобы получить вывод.
- Буферы рендерятся в текстуры с плавающей точкой (`GL_RGBA16F`), затем используются по схеме ping-pong (переключение read/write каждый кадр).

### 4.1 Маршрутизация каналов в каждом проходе

Для каждого прохода доступна маршрутизация `iChannel0..3`. Для каждого канала можно выбрать:

- `None`
- `Resource 0`
- `Resource 1`
- `Resource 2`
- `Resource 3`
- `Buffer A`
- `Buffer B`
- `Buffer C`
- `Buffer D`

Каналы ресурсов берутся из настроек `iChannel# Resource`.

По умолчанию:

- все маршрутизации `iChannel` имеют значение `None`
- ни один буферный проход не активен, пока его исходник не станет непустым

Важно:

- При маршрутизации на тот же буферный проход (feedback) читаются данные предыдущего кадра (текстура чтения ping-pong).
- Если маршрутизированный источник отсутствует/неактивен, подставляется резервная текстура, а `iChannelResolution[n].z` становится `0.0`.

## 5. Координаты и семантика области

Шейдеры работают в прямоугольной области:

- Фон меню: область во весь экран
- Элемент GLSL: прямоугольник элемента

Соглашения по координатам:

- Пиксельные uniform-ы задаются в пикселях локальной области.
- Начало оси Y для пиксельных координат, видимых шейдером, находится снизу слева.
- Координаты мыши не ограничиваются областью; значения могут выходить за её пределы, если курсор находится вне области.

Специальные поля:

- `fmAreaOffset`: положение нижнего левого угла области в экранных пикселях
- `fmAreaTopLeft`: положение верхнего левого угла области в экранных пикселях
- `fmAreaSize`: размер области в пикселях

## 6. Справочник uniform-ов API

Все uniform-ы ниже доступны как для фоновых, так и для элементных шейдеров.

## 6.1 Uniform-ы, совместимые с Shadertoy

| Uniform | Тип | Значение |
|---|---|---|
| `iResolution` | `vec3` | `(areaWidthPx, areaHeightPx, 1.0)` |
| `iTime` | `float` | Накопленное время шейдера в секундах |
| `iTimeDelta` | `float` | Дельта времени последней отрисовки, зависит от freeze/time scale |
| `iFrameRate` | `float` | FPS рантайма с резервным значением от FPS Minecraft |
| `iFrame` | `int` | Счётчик кадров для текущего рантайма |
| `iMouse` | `vec4` | См. подробности ниже |
| `iDate` | `vec4` | `(year, month, day, secondsOfDayWithFraction)` |
| `iSampleRate` | `float` | Константа `44100.0` |
| `iChannelTime[4]` | `float[4]` | Сейчас все установлены в `iTime` |
| `iChannelResolution[4]` | `vec3[4]` | `(width, height, validFlag)` для каждого канала |
| `iChannel0..3` | `sampler2D` | Маршрутизированные входные текстуры |

### Подробности `iMouse`

`iMouse = vec4(x, y, z, w)`

- `x`, `y`: текущая позиция мыши в пикселях локальной области, либо поведение удержания/фиксации, если включён соответствующий переключатель
- `z`, `w`: начало левого клика
  - положительные, пока удерживается левая кнопка мыши
  - отрицательные после отпускания

Поведение, управляемое переключателем:

- `Update iMouse Position Only While Holding LMB = Off`:
  - `iMouse.xy` обновляется непрерывно
- `... = On`:
  - `iMouse.xy` обновляется только пока ЛКМ нажата, затем остаётся на последней позиции удержания

Значение по умолчанию:

- `Off` (непрерывное обновление)

## 6.3 API uniform-ов переменных FancyMenu

Переменные FancyMenu доступны напрямую как runtime uniform-ы (для фона, элементов и декоративных оверлеев) без перекомпиляции шейдера при изменении значений.

### Именование

Для каждой переменной `<name>` FancyMenu предоставляет:

- `fmVarFloat_<name>`
- `fmVarInt_<name>`
- `fmVarBool_<name>`
- `fmVarVec2_<name>`
- `fmVarVec3_<name>`
- `fmVarVec4_<name>`
- `fmVarExists_<name>` (`1` = переменная сейчас существует, `0` = отсутствует/удалена)

Очистка суффикса uniform-а для `<name>`:

- допустимые символы: `[A-Za-z0-9_]`
- все остальные символы заменяются на `_`
- если первый символ — цифра, в начало добавляется `_`

Примеры:

- переменная `player_hp` -> суффикс `player_hp`
- переменная `player-hp` -> суффикс `player_hp`
- переменная `2nd_phase` -> суффикс `_2nd_phase`

Важно:

- эти динамические uniform-ы переменных **не объявляются автоматически** в исходнике шейдера (объявляйте используемые вручную)
- избегайте имён переменных, которые после очистки дают один и тот же суффикс, поскольку они будут ссылаться на одно и то же GLSL-имя uniform-а

### Преобразование значений

Если текстовое значение переменной `v`:

- `fmVarFloat_*`: распарсенный float (запасное значение `0.0`)
- `fmVarInt_*`: распарсенный int (запасное значение `0`)
- `fmVarBool_*`: логическая/целочисленная интерпретация (`true/yes/on/enabled` => `1`, `false/no/off/disabled` => `0`, иначе любое ненулевое число => `1`)
- разбор вектора поддерживает разделители: пробелы, `,`, `;`, `|`
  - `fmVarVec2_*`: первые 2 распознанных компонента
  - `fmVarVec3_*`: первые 3 распознанных компонента
  - `fmVarVec4_*`: первые 4 распознанных компонента
  - если компонентов меньше, последняя распознанная компонента повторяется для отсутствующих слотов
  - если числовые компоненты отсутствуют, все компоненты вектора используют скалярное запасное значение

Если переменная удаляется:

- `fmVarExists_*` становится `0`
- все соответствующие значения `fmVar*_*` сбрасываются в `0`

### Пример объявления и использования

```glsl
uniform float fmVarFloat_player_hp;
uniform int fmVarBool_is_boss_phase;
uniform vec3 fmVarVec3_theme_color;
uniform int fmVarExists_player_hp;

void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;

    float hp = clamp(fmVarFloat_player_hp / 100.0, 0.0, 1.0);
    vec3 theme = fmVarVec3_theme_color;
    float boss = float(fmVarBool_is_boss_phase);

    vec3 col = mix(theme * 0.25, theme, hp);
    col += vec3(0.2, 0.0, 0.0) * boss;

    if (fmVarExists_player_hp == 0) {
        col = vec3(0.15);
    }

    fragColor = vec4(col, 1.0);
}
```

## 7. Модель отслеживания ввода

FancyMenu глобально отслеживает ввод и сохраняет его состояние для каждого рендера:

- движение/перетаскивание мыши
- нажатие/отпускание мыши
- прокрутка
- нажатие/отпускание/повтор клавиш
- ввод символов

Надёжность мыши:

- рантайм сверяет состояния кнопок с опросом GLFW на каждом кадре, чтобы предотвратить зависшие состояния кнопок.

Если `Pass Input Events To Shader` отключён:

- uniform-ы ввода сбрасываются к нейтральным значениям каждый кадр
- счётчики и события обнуляются в данных, видимых шейдеру

## 8. Подробности входных текстур

Каналы ресурсов (`iChannel# Resource`) ожидают 2D-текстуры.

Состояние текстуры для каждого канала:

- действующий ресурс: привязанная текстура, реальные width/height, `iChannelResolution[n].z = 1.0`
- отсутствует/неактивен/None: резервная текстура, `iChannelResolution[n].xyz = (0,0,0)`

Текстуры буферов:

- внутренний формат: `RGBA16F` (с плавающей точкой)
- фильтрация: линейная
- wrap: clamp-to-edge

Это подходит для многопроходных данных, включая значения вне диапазона `[0,1]`.

## 9. Примечания по рендерингу и смешиванию

- Буферные проходы рендерятся вне экрана без blending.
- Финальный проход `Image` использует настройку `Enable Blending` для композитинга.
- Обёртка Shadertoy автоматически применяет `fmOpacity` к альфа-каналу.
- В прямых шейдерах при необходимости `fmOpacity` следует применить вручную.

## 10. Практические шаблоны

## 10.1 Минимальный шейдер в стиле Shadertoy

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;
    vec3 col = vec3(uv, 0.5 + 0.5 * sin(iTime));
    fragColor = vec4(col, 1.0);
}
```

## 10.2 Минимальный прямой фрагментный шейдер

```glsl
out vec4 FragColor;

void main() {
    vec2 uv = gl_FragCoord.xy - fmAreaOffset;
    uv /= iResolution.xy;

    vec3 col = vec3(uv.x, uv.y, 0.5 + 0.5 * sin(iTime));
    FragColor = vec4(col, fmOpacity);
}
```

## 10.3 Минимальный многопроходный feedback

### Исходник Buffer A

Маршрут: `Buffer A iChannel0 Input -> Buffer A`

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;
    vec4 prev = texture(iChannel0, uv);
    vec4 seed = vec4(uv, 0.0, 1.0);
    fragColor = mix(prev, seed, 0.02);
}
```

### Исходник Image

Маршрут: `Image iChannel0 Input -> Buffer A`

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;
    fragColor = texture(iChannel0, uv);
}
```

## 11. Чеклист поиска неисправностей

- Нет вывода:
  - проверьте, что исходник Image не пуст
  - проверьте, что режим компиляции соответствует вашей точке входа (`mainImage` vs `main`)
- Фиолетовые/некорректные текстуры:
  - проверьте привязки ресурсов и маршрутизацию каналов
  - проверьте `iChannelResolution[n].z` (`0.0` означает недействительно/недоступно)
- Неверные координаты в прямом шейдере:
  - используйте `gl_FragCoord.xy - fmAreaOffset` для локальных координат области
- Некорректное поведение перетаскивания:
  - используйте переключатель `Update iMouse Position Only While Holding LMB`
- Прозрачность не применяется в прямом шейдере:
  - умножьте альфа-канал на `fmOpacity` вручную
