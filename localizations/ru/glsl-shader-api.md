# API шейдеров GLSL для FancyMenu

В этом документе описывается среда выполнения GLSL, используемая в FancyMenu для:

- фонового изображения меню `GLSL`
- элемента `GLSL`
- декоративного наложения `GLSL`

Здесь рассматриваются режимы компиляции, маршрутизация многопроходного рендеринга, поддерживаемые uniform-переменные и практические приемы написания шейдеров.

## 1. Обзор среды выполнения

FancyMenu рендерит шейдеры с помощью внутреннего конвейера OpenGL (`#version 150`) и поддерживает:

- шейдеры с одним проходом (только проход `Image`)
- шейдеры с несколькими проходами (`Buffer A` / `B` / `C` / `D` + `Image`)
- точки входа в стиле Shadertoy (`mainImage`)
- непосредственные точки входа фрагментного шейдера (`main`)

Исходный код шейдеров задается в текстовых полях:

- `Shader Source` (проход Image, необходим для рендеринга)
- `Buffer A Source` (необязательно)
- `Buffer B Source` (необязательно)
- `Buffer C Source` (необязательно)
- `Buffer D Source` (необязательно)

Если поле Image source пусто, рендеринг завершится ошибкой «no source».

## 2. Режимы компиляции

FancyMenu поддерживает три режима компиляции:

- `Auto`
- `Direct Fragment`
- `Shadertoy`

### 2.1 Режим Shadertoy

Ожидаемая точка входа:

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord)
```

FancyMenu оборачивает ее в `main()` и передает координаты относительно локальной области:

```glsl
mainImage(fmColor_FancyMenu, gl_FragCoord.xy - fmAreaOffset);
```

Обертка умножает выходную альфа-компоненту на `fmOpacity`.

### 2.2 Непосредственный режим

Ожидаемая точка входа:

```glsl
void main()
```

Особенности совместимости:

- Сначала пробуется вариант с поддержкой совместимости `gl_FragColor`.
- Также пробуется вариант без совместимости (для современных шейдеров с явным `out vec4`).

В непосредственном режиме `fmOpacity` автоматически не применяется к выходным данным. При необходимости примените его вручную.

### 2.3 Автоматический режим

В режиме Auto по очереди пробуются совместимые варианты (Shadertoy/Direct), и используется первый успешно скомпилированный.

## 3. Предварительная обработка исходного кода и встроенные макросы

Перед компиляцией FancyMenu нормализует исходный код:

- удаляет BOM UTF-8
- преобразует CRLF/CR в LF
- удаляет строки `#version ...`
- удаляет строки `precision ...;`

Среда выполнения добавляет в начало кода:

- `#version 150`
- `in vec2 fmUv_FancyMenu` (UV-координаты на весь экран в диапазоне `[0,1]`, начало координат внизу слева)
- `#define iGlobalTime iTime`
- `#define texture2D texture`
- `#define textureCube texture`

Примечание:

- Если в исходном коде уже объявлена известная uniform-переменная (например, `iTime`), FancyMenu не добавляет ее повторное объявление.
- При этом FancyMenu все равно пытается передавать значения этой переменной во время выполнения.
- Здесь `textureCube` — только макрос-псевдоним; `iChannel0..3` — uniform-переменные типа `sampler2D`.

## 4. Система проходов (Image + Buffer A-D)

В FancyMenu предусмотрено 5 слотов проходов:

- `Buffer A`
- `Buffer B`
- `Buffer C`
- `Buffer D`
- `Image` (финальный проход, выводимый на экран)

Поведение:

- Проходы Buffer выполняются только при наличии исходного кода.
- Для вывода изображения необходимо задать проход Image.
- Буферы рендерятся в текстуры с плавающей точкой (`GL_RGBA16F`), а затем обмениваются местами (текстуры чтения и записи меняются местами каждый кадр).

### 4.1 Маршрутизация каналов для каждого прохода

Для каждого прохода можно настроить маршрутизацию `iChannel0..3`. Для каждого канала доступны варианты:

- `None`
- `Resource 0`
- `Resource 1`
- `Resource 2`
- `Resource 3`
- `Buffer A`
- `Buffer B`
- `Buffer C`
- `Buffer D`

Каналы Resource используют настройки `iChannel# Resource`.

Значения по умолчанию:

- для всех каналов `iChannel` выбрано `None`
- проходы Buffer не активны, пока в соответствующее поле не добавлен исходный код

Важно:

- При маршрутизации канала на тот же проход Buffer (обратная связь) считываются данные предыдущего кадра (текстура чтения с чередованием буферов).
- Если указанный источник отсутствует или неактивен, привязывается резервная текстура, а значение `iChannelResolution[n].z` становится равным `0.0`.

## 5. Координаты и семантика областей

Шейдеры выполняются в прямоугольной области:

- Фон меню: область всего экрана
- Элемент GLSL: прямоугольник элемента

Система координат:

- Пиксельные uniform-переменные задаются в локальных координатах области.
- Начало координат для пиксельных координат шейдера находится внизу слева.
- Координаты мыши не ограничиваются областью; если курсор находится за ее пределами, значения могут выходить за границы.

Специальные поля:

- `fmAreaOffset`: положение нижнего левого угла области в экранных пиксельных координатах
- `fmAreaTopLeft`: положение верхнего левого угла области в экранных пиксельных координатах
- `fmAreaSize`: размер области в пикселях

## 6. Справочник uniform API

Все перечисленные ниже uniform-переменные доступны шейдерам фона и элементов.

## 6.1 Uniform-переменные, совместимые с Shadertoy

| Uniform | Тип | Значение |
|---|---|---|
| `iResolution` | `vec3` | `(areaWidthPx, areaHeightPx, 1.0)` |
| `iTime` | `float` | Накопленное время работы шейдера в секундах |
| `iTimeDelta` | `float` | Время с последнего рендеринга; зависит от заморозки и масштаба времени |
| `iFrameRate` | `float` | FPS Minecraft; если они недоступны, используются FPS среды выполнения |
| `iFrame` | `int` | Счетчик кадров среды выполнения |
| `iMouse` | `vec4` | Подробнее см. ниже |
| `iDate` | `vec4` | `(год, месяц, день, секунды с начала дня с дробной частью)` |
| `iSampleRate` | `float` | Постоянное значение `44100.0` |
| `iChannelTime[4]` | `float[4]` | Сейчас все значения равны `iTime` |
| `iChannelResolution[4]` | `vec3[4]` | `(ширина, высота, флагДоступности)` для каждого канала |
| `iChannel0..3` | `sampler2D` | Текстуры, назначенные каналам |

### Подробнее о `iMouse`

`iMouse = vec4(x, y, z, w)`

- `x`, `y`: текущие координаты мыши в пикселях относительно области; если включен переключатель, координаты сохраняются или замораживаются
- `z`, `w`: координаты начала нажатия левой кнопки мыши
  - положительные, пока левая кнопка мыши нажата
  - отрицательные после отпускания

Поведение, задаваемое переключателем:

- `Update iMouse Position Only While Holding LMB = Off`:
  - `iMouse.xy` обновляется непрерывно
- `... = On`:
  - `iMouse.xy` обновляется только при нажатой левой кнопке мыши, а после этого сохраняет последнее положение во время нажатия

Значение по умолчанию:

- `Off` (непрерывное обновление)

## 6.3 API uniform-переменных FancyMenu

Переменные FancyMenu напрямую предоставляются в виде uniform-переменных среды выполнения (для шейдеров фона, элементов и декоративных наложений). При изменении значений шейдер не компилируется повторно.

### Имена

Для каждой переменной `<name>` FancyMenu предоставляет:

- `fmVarFloat_<name>`
- `fmVarInt_<name>`
- `fmVarBool_<name>`
- `fmVarVec2_<name>`
- `fmVarVec3_<name>`
- `fmVarVec4_<name>`
- `fmVarExists_<name>` (`1` = переменная существует, `0` = отсутствует или удалена)

Правила нормализации суффикса uniform-переменной `<name>`:

- разрешены символы `[A-Za-z0-9_]`
- все остальные символы заменяются на `_`
- если первый символ — цифра, перед именем добавляется `_`

Примеры:

- переменная `player_hp` -> суффикс `player_hp`
- переменная `player-hp` -> суффикс `player_hp`
- переменная `2nd_phase` -> суффикс `_2nd_phase`

Важно:

- динамические uniform-переменные не объявляются в исходном коде шейдера автоматически (объявите вручную те, которые используете)
- не используйте имена переменных, которые после нормализации дают одинаковый суффикс, иначе они будут соответствовать одному имени uniform-переменной GLSL

### Преобразование значений

Для текстового значения переменной `v`:

- `fmVarFloat_*`: число с плавающей точкой (`0.0`, если преобразование не удалось)
- `fmVarInt_*`: целое число (`0`, если преобразование не удалось)
- `fmVarBool_*`: логическое/целочисленное значение (`true/yes/on/enabled` => `1`, `false/no/off/disabled` => `0`, иначе ненулевое число => `1`)
- для векторов принимаются разделители: пробелы, `,`, `;`, `|`
  - `fmVarVec2_*`: первые 2 распознанных компонента
  - `fmVarVec3_*`: первые 3 распознанных компонента
  - `fmVarVec4_*`: первые 4 распознанных компонента
  - если компонентов меньше нужного количества, последний распознанный компонент повторяется для недостающих значений
  - если числовых компонентов нет, для всех компонентов вектора используется скалярное значение по умолчанию

[Переменные-списки](/variables#text-and-list-variables) возвращают количество элементов вместо текста:

- `fmVarFloat_*` и `fmVarInt_*`: количество элементов, например `3` для списка из 3 элементов
- `fmVarBool_*`: `1`, если список не пуст, `0`, если он пуст
- `fmVarVec2_*`, `fmVarVec3_*` и `fmVarVec4_*`: количество элементов в каждом компоненте

Если переменная удалена:

- `fmVarExists_*` становится равной `0`
- все соответствующие значения `fmVar*_*` сбрасываются в `0`

### Пример объявления и использования

```glsl
uniform float fmVarFloat_player_hp;
uniform int fmVarBool_is_boss_phase;
uniform vec3 fmVarVec3_theme_color;
uniform int fmVarExists_player_hp;

void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;

    float hp = clamp(fmVarFloat_player_hp / 100.0, 0.0, 1.0);
    vec3 theme = fmVarVec3_theme_color;
    float boss = float(fmVarBool_is_boss_phase);

    vec3 col = mix(theme * 0.25, theme, hp);
    col += vec3(0.2, 0.0, 0.0) * boss;

    if (fmVarExists_player_hp == 0) {
        col = vec3(0.15);
    }

    fragColor = vec4(col, 1.0);
}
```

## 7. Модель отслеживания ввода

FancyMenu отслеживает ввод глобально и сохраняет его состояние для каждого рендеринга:

- перемещение мыши и перетаскивание
- нажатие и отпускание кнопок мыши
- прокрутка
- нажатие, отпускание и повтор клавиш
- ввод символов

Надежная обработка мыши:

- Среда выполнения каждый кадр сверяет состояние кнопок с данными GLFW, чтобы кнопки не оставались в ошибочно нажатом состоянии.

Если параметр `Pass Input Events To Shader` отключен:

- каждый кадр uniform-переменные ввода сбрасываются в нейтральные значения
- счетчики и события обнуляются в данных, доступных шейдеру

## 8. Сведения о входных текстурах

Каналы Resource (`iChannel# Resource`) принимают двумерные текстуры.

Состояние текстуры для каждого канала:

- доступный ресурс: привязанная текстура, фактические ширина и высота, `iChannelResolution[n].z = 1.0`
- отсутствующий, неактивный или не назначенный источник: резервная текстура, `iChannelResolution[n].xyz = (0,0,0)`

Текстуры буферов:

- внутренний формат: `RGBA16F` (с плавающей точкой)
- фильтрация: линейная
- режим обертки: clamp-to-edge

Этот формат подходит для многопроходных данных (в том числе значений за пределами `[0,1]`).

## 9. Примечания о рендеринге и смешивании

- Проходы Buffer рендерятся вне экрана без смешивания.
- Для компоновки финального прохода Image используется настройка `Enable Blending`.
- Обертка Shadertoy автоматически применяет `fmOpacity` к альфа-компоненте.
- Если это необходимо, прямые шейдеры должны применять `fmOpacity` вручную.

## 10. Практические шаблоны

## 10.1 Минимальный шейдер в стиле Shadertoy

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;
    vec3 col = vec3(uv, 0.5 + 0.5 * sin(iTime));
    fragColor = vec4(col, 1.0);
}
```

## 10.2 Минимальный непосредственный фрагментный шейдер

```glsl
out vec4 FragColor;

void main() {
    vec2 uv = gl_FragCoord.xy - fmAreaOffset;
    uv /= iResolution.xy;

    vec3 col = vec3(uv.x, uv.y, 0.5 + 0.5 * sin(iTime));
    FragColor = vec4(col, fmOpacity);
}
```

## 10.3 Минимальный многопроходный шейдер с обратной связью

### Исходный код Buffer A

Маршрут: `Buffer A iChannel0 Input -> Buffer A`

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;
    vec4 prev = texture(iChannel0, uv);
    vec4 seed = vec4(uv, 0.0, 1.0);
    fragColor = mix(prev, seed, 0.02);
}
```

### Исходный код Image

Маршрут: `Image iChannel0 Input -> Buffer A`

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;
    fragColor = texture(iChannel0, uv);
}
```

## 11. Список проверок при устранении неполадок

- Нет изображения:
  - убедитесь, что поле Image source не пусто
  - проверьте, соответствует ли режим компиляции точке входа (`mainImage` или `main`)
- Фиолетовые или недоступные текстуры:
  - проверьте привязку ресурсов и маршрутизацию каналов
  - проверьте `iChannelResolution[n].z` (`0.0` означает, что текстура недоступна или некорректна)
- Неверные координаты в прямом шейдере:
  - для локальных координат области используйте `gl_FragCoord.xy - fmAreaOffset`
- Неверно работает перетаскивание:
  - используйте переключатель `Update iMouse Position Only While Holding LMB`
- В прямом шейдере не применяется непрозрачность:
  - самостоятельно умножьте альфа-компоненту на `fmOpacity`
