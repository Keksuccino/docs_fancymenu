# Получение данных NBT

Эти плейсхолдеры доступны в FancyMenu версии v3.8.0+.

Плейсхолдеры **Client NBT Data Get** и **Server NBT Data Get** позволяют получать данные NBT (Named Binary Tag) из сущностей и блоков в Minecraft, аналогично команде `/data get`. Это очень полезно для создания динамических интерфейсов, которые реагируют на состояние игры, характеристики игрока или условия мира.

> Этот плейсхолдер особенно мощный в модифицированной игре, поскольку он может получать доступ к пользовательским данным NBT, которые моды добавляют сущностям и игрокам. Независимо от того, используете ли вы магические моды с системой маны, RPG-моды с кастомными характеристиками или технологические моды со значениями энергии, вы можете отображать эти значения в своих UI-элементах.
{.is-info}

## Обзор

Эти плейсхолдеры извлекают конкретные значения из структур NBT с помощью путей NBT. Вы можете получать здоровье игрока, уровень голода, предметы инвентаря, состояния блоков, модифицированные атрибуты вроде маны или энергии и многое другое.

Клиентская версия плейсхолдера имеет большое преимущество: она работает полностью на стороне клиента, поэтому FancyMenu не нужен на сервере. Однако из-за этого она гораздо более ограничена, поскольку не всё, что связано с данными NBT, всегда видно всем клиентам.

Серверная версия требует установки FancyMenu на сервере, но это даёт ей **полную поддержку** практически **всего**, что хранится как NBT.

На этой странице основное внимание уделяется клиентской версии (`nbt_data_get`), но для серверной версии (`nbt_data_get_server`) всё работает очень похоже.

## Синтаксис плейсхолдера

```
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health"}}
```

## Обязательные значения

| Значение | Описание | Варианты |
|-------|-------------|---------|
| `source_type` | Тип источника данных | `entity` или `block` |
| `nbt_path` | Путь NBT для запроса | например `Health`, `foodLevel`, `Pos[0]`, `Inventory[0].id` |

## Условные значения

В зависимости от `source_type` вам понадобится одно из следующих значений:

| Значение | Требуется, когда | Описание | Формат |
|-------|--------------|-------------|--------|
| `entity_selector` | `source_type` равен `entity` | Выбирает, у какой сущности запрашивать данные | `@s` (себя), `@p` (ближайший игрок), `@e` (ближайшая сущность), UUID или имя сущности |
| `block_pos` | `source_type` равен `block` | Координаты блока | `x y z` (например `100 64 -200`) |

## Дополнительные значения

| Значение | Описание | По умолчанию | Варианты |
|-------|-------------|---------|---------|
| `scale` | Коэффициент масштабирования числовых значений | `1.0` | Любое десятичное число |
| `return_type` | Как форматировать возвращаемые данные | `value` | `value` (число/размер), `string` (текст), `snbt` (форматированный NBT), `json` (формат JSON) |

## Пояснение типов возврата

- **`value`** — возвращает числовые значения или размеры (по умолчанию)
  - Для чисел: возвращает число (с возможным масштабированием)
  - Для строк: возвращает длину строки
  - Для списков/массивов: возвращает количество элементов
  - Для compound-значений: возвращает число тегов

- **`string`** — возвращает фактическое строковое значение данных NBT

- **`snbt`** — возвращает данные в формате SNBT (Stringified NBT)

- **`json`** — возвращает данные в формате JSON (только для compound-тегов)

## Примеры

### Получить здоровье игрока
```json
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health"}}
```

### Получить уровень голода игрока
```json
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"foodLevel"}}
```

### Получить координату X игрока
```json
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Pos[0]"}}
```

### Получить предмет в первом слоте хотбара
```json
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Inventory[{Slot:0b}].id","return_type":"string"}}
```

### Получить данные блока в конкретной позиции
```json
{"placeholder":"nbt_data_get","values":{"source_type":"block","block_pos":"100 64 -200","nbt_path":"Items[0].Count"}}
```

### Получить масштабированный процент здоровья (Health * 5)
```json
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health","scale":"5"}}
```

## Поиск доступных путей NBT

### Метод 1: использование команды `/data get` (рекомендуется)

Самый простой способ узнать доступные пути NBT — использовать команду `/data get` в игре без указания пути:

1. **Для сущностей:** `/data get entity @p`
2. **Для блоков:** `/data get block <x> <y> <z>`

Это покажет все доступные данные NBT для выбранной цели и точные пути, которые вы можете использовать.

#### Понимание вывода

Когда вы запускаете `/data get entity @p`, вы увидите вывод, похожий на этот:

```
Player616 has the following entity data: {Brain: {memories: {}}, 
HurtByTimestamp: 0, SleepTimer: 0s, Invulnerable: 0b, FallFlying: 
0b, PortalCooldown: 0, AbsorptionAmount: 0.0f, abilities: 
{invulnerable: 1b, mayfly: 1b, instabuild: 1b, walkSpeed: 0.1f, 
mayBuild: 1b, flying: 1b, flySpeed: 0.05f}, FallDistance: 0.0f, 
recipeBook: {recipes: ["minecraft:crafting_table"]}, 
DeathTime: 0s, XpSeed: -380875747, XpTotal: 0, UUID: [I; 1379890089, -1732753738, 
-2135065633, -718799804], playerGameType: 1, seenCredits: 
0b, Motion: [0.0d, 0.0d, 0.0d], Health: 20.0f, foodSaturationLevel: 
5.0f, ...}
```

Чтобы извлечь корректный путь из этого вывода:

1. **Простые значения** — используйте имя ключа напрямую:
   - `Health: 20.0f` → Путь: `Health`
   - Пример: `{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health"}}`

2. **Вложенные значения** — используйте точечную нотацию для доступа к вложенным данным:
   - `abilities: {walkSpeed: 0.1f}` → Путь: `abilities.walkSpeed`
   - Пример: `{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"abilities.walkSpeed"}}`

3. **Массивы** — используйте квадратные скобки с индексом:
   - `Motion: [0.0d, 0.0d, 0.0d]` → Путь для Y-движения: `Motion[1]`
   - Пример: `{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Motion[1]"}}`

### Метод 2: мод NBT Autocomplete

Для более простого поиска путей NBT рассмотрите установку мода **NBT Autocomplete**:
- Доступен для Fabric и Forge (Minecraft 1.21.x)
- Предлагает автодополнение прямо в игре при вводе команд
- Показывает доступные имена и типы тегов
- [Modrinth](https://modrinth.com/mod/nbt-autocomplete) | [CurseForge](https://www.curseforge.com/minecraft/mc-mods/nbt-autocomplete)

## Распространённые пути NBT

### Сущность игрока
- `Health` — текущее здоровье (float)
- `foodLevel` — уровень голода (int, 0-20)
- `foodSaturationLevel` — уровень насыщения (float)
- `XpLevel` — уровень опыта (int)
- `XpP` — прогресс опыта (float, 0.0-1.0)
- `Pos[0]`, `Pos[1]`, `Pos[2]` — координаты X, Y, Z
- `Inventory` — массив инвентаря игрока
- `SelectedItemSlot` — текущий выбранный слот хотбара (int, 0-8)

### Часто встречающиеся NBT у блоков
- `Items` — содержимое контейнера (сундуки, печи и т. д.)
- `CustomName` — пользовательское имя блока
- `Lock` — строка блокировки для контейнеров

### Примеры NBT из модов
- **Магические моды**: часто хранят ману как `playerMana`, `mana.current` или подобные значения
- **Технологические моды**: значения энергии вроде `energy`, `forgeEnergy` или `energyStorage.energy`
- **RPG-моды**: пользовательские характеристики вроде `customStats.strength`, `rpgAttributes.level`

Чтобы найти пути NBT из модов, используйте `/data get entity @p`, пока мод активен, и ищите пользовательские теги, добавленные модом.

## Ограничения

- **Нет доступа к storage на клиенте** — источник данных storage не поддерживается на клиенте (только на сервере)
- **Производительность** — частый доступ к данным NBT может влиять на производительность
- Возвращает пустую строку, если путь неверный или данные недоступны

## Советы

1. Всегда сначала проверяйте пути NBT в игре с помощью `/data get`
2. Используйте параметр `scale`, чтобы преобразовывать значения в проценты или другие удобные форматы
3. Помните, что часть данных NBT может не синхронизироваться с клиентом
4. Селекторы сущностей ограничены сущностями в пределах дистанции отрисовки
5. Для контента из модов изучите документацию мода или используйте `/data get`, чтобы найти пользовательские пути NBT
