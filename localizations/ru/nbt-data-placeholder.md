# Плейсхолдеры данных NBT

FancyMenu предоставляет два NBT-плейсхолдера:

| Плейсхолдер | Выполняется на | Доступные данные |
|---|---|---|
| `nbt_data_get` | Клиент | Сущности и блок-энтити, видимые клиенту |
| `nbt_data_get_server` | Сервер | Цели ванильной команды `/data get`; требуется FancyMenu на сервере |

# Плейсхолдер на стороне клиента

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health"}}
```

## Значения

| Значение | Обязательно | Описание |
|---|---|---|
| `source_type` | Да | `entity` или `block` |
| `entity_selector` | Для сущностей | Клиентский селектор, UUID или точное имя сущности |
| `block_pos` | Для блоков | Три абсолютные целочисленные координаты, например `100 64 -200` |
| `nbt_path` | Да | Путь NBT, например `Health`, `Pos[0]` или `Inventory[0].id` |
| `scale` | Нет | Умножает числовые результаты `value`; по умолчанию `1.0` |
| `return_type` | Нет | `value`, `string`, `snbt` или `json`; по умолчанию `value` |

Координаты блоков на стороне клиента не поддерживают `~` или `^`.

## Клиентские селекторы сущностей

| Селектор | Начальные цели | Значение по умолчанию для порядка |
|---|---|---|
| `@s` | Локальный игрок | Сам |
| `@p` | Игроки | Ближайший |
| `@a` | Игроки | Порядок обхода клиента |
| `@r` | Игроки | Случайный |
| `@e` | Все сущности, видимые клиенту | Порядок обхода клиента |

`@e` не выбирает ближайшую сущность, если вы не добавите `sort=nearest`. Также поддерживается прямой поиск по UUID и точному имени сущности.

Поддерживаемые параметры селектора:

| Параметр | Описание |
|---|---|
| `type` | ID сущности; добавьте `!`, чтобы исключить |
| `name` | Точное отображаемое имя; добавьте `!`, чтобы исключить |
| `tag` | Тег сущности; добавьте `!`, чтобы исключить |
| `limit` | Положительный предел результатов |
| `sort` | `nearest`, `furthest`, `random` или `arbitrary` |
| `distance` | Ванильный диапазон расстояния, например `..10` или `5..20` |
| `x`, `y`, `z` | Точка поиска; принимает абсолютные значения и смещения `~` |
| `dx`, `dy`, `dz` | Размер области поиска от точки начала |

Локальные координаты `^` и другие ванильные параметры селектора не поддерживаются клиентским плейсхолдером.

Пример:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@e[type=minecraft:zombie,sort=nearest,limit=1,distance=..20]","nbt_path":"Health"}}
```

## Типы возвращаемого значения

| Тип | Результат |
|---|---|
| `value` | Числовые теги форматируются как числа и используют `scale`; строковые теги возвращают свой текст; другие теги возвращают SNBT-подобный текст |
| `string` | Возвращает строковое значение тега или пустую строку, если у тега нет строкового значения |
| `snbt` | Возвращает SNBT-представление тега |
| `json` | Только для compound-тегов: возвращает сериализованный текстовый компонент Minecraft с красиво отформатированным выводом NBT |

Режим `json` на стороне клиента не является прямым преобразованием NBT в JSON.

## Примеры

Голод игрока:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"foodLevel"}}
```

ID предмета в первом слоте хотбара:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Inventory[{Slot:0b}].id","return_type":"string"}}
```

Количество предметов в блок-энтити:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"block","block_pos":"100 64 -200","nbt_path":"Items[0].count"}}
```

# Плейсхолдер на стороне сервера

`nbt_data_get_server` следует поведению серверной команды `/data get` и поддерживает:

- Полные серверные селекторы сущностей.
- Цели блоков с абсолютными, относительными (`~`) или локальными (`^`) координатами.
- Хранилище команд через `source_type:"storage"`.

```text
{"placeholder":"nbt_data_get_server","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health","return_type":"value"}}
```

Плейсхолдер возвращает пустое значение, пока не придёт ответ от сервера. Ответы на короткое время кэшируются, чтобы избежать слишком частых запросов.

# Поиск путей NBT

Используйте соответствующую команду без пути NBT, чтобы просмотреть доступные данные:

```text
/data get entity @s
/data get block 100 64 -200
```

Результаты на стороне клиента ограничены данными, синхронизированными с клиентом. Неверные цели или пути возвращают пустую строку и записывают подробности в `logs/latest.log`.
