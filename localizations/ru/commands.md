# Команды

FancyMenu добавляет в игру команды, которые могут быть очень полезны при использовании вместе с другими модами, например FTB Quests.

> [!WARNING]
> Для использования команд в сетевой игре FancyMenu должен быть установлен на **СЕРВЕРЕ** (и на клиенте)!

## Целевые игроки и разрешения

Аргумент целевых игроков в командах `/openguiscreen`, `/closeguiscreen` и `/fmlayout` необязателен. Если игрок его не укажет, команда затронет этого игрока. Если цель указана, можно использовать обычные имена игроков и селекторы, например `@a`.

- Для указания цели в командах `/openguiscreen` и `/closeguiscreen` требуется **уровень разрешений 2** (игровой мастер / OP уровня 2), даже если в качестве цели указан источник команды.
- Для указания цели в команде `/fmlayout` требуется **уровень разрешений 3** (администратор / OP уровня 3), даже если в качестве цели указан источник команды.
- Для всех подкоманд `/fmdata` требуется **уровень разрешений 2** (игровой мастер / OP уровня 2).

Для трёх команд с необязательными целевыми игроками пропустить цель можно, только если источник команды — игрок. В консоли сервера цель нужно указать, а также иметь требуемый для аргумента цели уровень разрешений.

## /openguiscreen

Команда `/openguiscreen` открывает ванильный экран, экран мода или [пользовательский экран](/custom-guis). Она может открывать экраны для других игроков, если FancyMenu установлен на сервере и их клиентах.

См. разделы [Открытие экранов командами](/opengui-command) и [Идентификаторы экранов](/screen-identifiers).

Некоторые экраны модов нельзя создать напрямую. Если целевой экран не поддерживается, FancyMenu покажет ошибку. В локальном макете используйте действие [**Имитировать ванильную кнопку/кнопку мода**](/action-scripts#mimic-vanillamod-button) для виджета, который обычно открывает этот экран.

**Использование:** `/openguiscreen <screen_identifier> [<target_players>]`

## /closeguiscreen

Команда `/closeguiscreen` закрывает текущий экран для источника команды или выбранных игроков. Она пригодится при использовании модов для заданий, событий или автоматизации, которые могут выполнять команды.

**Использование:** `/closeguiscreen [<target_players>]`

## /fmlayout

Команда `/fmlayout` включает или отключает макет у одного или нескольких клиентов. Используйте название макета точно в том виде, в котором оно указано в FancyMenu. Если в названии есть пробелы, заключите его в кавычки.

**Использование:** `/fmlayout <layout_name> <true|false> [<target_players>]`

Примеры:

- `/fmlayout quest_complete true` включает `quest_complete` для игрока, выполняющего команду.
- `/fmlayout quest_complete false @a` отключает его для всех игроков в сети. Для указания цели требуется уровень разрешений 3.

## /fmvariable

Команда `/fmvariable` задаёт значения [переменных FancyMenu](/variables) и позволяет получать их.

Чтобы выполнить эту команду от имени другого игрока, используйте ванильную команду `/execute as`:
`/execute as ExamplePlayer run fmvariable ...`

**Использование:**

- `/fmvariable get <variable_name>`
- `/fmvariable set <variable_name> <send_chat_feedback> <set_to_value>`

### Получение значения

Чтобы **получить значение переменной**, используйте подкоманду `get`:
`/fmvariable get some_variable`

Значение этой переменной появится в чате.

### Задание значения

Чтобы **задать значение переменной**, укажите логическое значение для отправки сообщения в чат перед новым значением:
`/fmvariable set some_variable true new_value`

Аргумент `send_chat_feedback` определяет, будет ли FancyMenu подтверждать изменение в чате. Аргумент `set_to_value` включает весь остаток команды, поэтому значение может содержать пробелы. Например, команда `/fmvariable set greeting false Hello from FancyMenu` сохранит значение `Hello from FancyMenu` и не отправит сообщение об успешном выполнении.

## /fmdata

Команда `/fmdata` передаёт пользовательские данные между сервером и клиентами FancyMenu, управляет обработчиками на стороне сервера, настраивает данные, отправляемые при входе игроков, и экспортирует эти настройки для [чатов с ИИ](/export-for-ai#servers). Для всех подкоманд `/fmdata` требуется уровень разрешений 2.

Полный список подкоманд, синтаксис и примеры см. в разделе [FM Data](/fm-data).
