# 远程服务器通信

“远程服务器通信”系统允许 FancyMenu 客户端通过 WebSocket 连接与外部服务器进行通信。

所有数据都基于文本：

- 支持纯文本
- 支持 JSON（作为普通文本）

在运行期间，每个服务器 URL 都会获得一个缓存的 **请求 ID**。
FancyMenu 会使用此 ID 跟踪连接，并在监听器变量中公开它。

# 快速开始

1. 添加动作 **连接到远程服务器**（可选，但有助于提前打开连接）
2. 使用相同的 URL 添加动作 **发送数据到远程服务器**
3. 添加监听器 **远程服务器接收到数据时** 来响应回复
4. 使用 **远程服务器已连接** / **远程服务器连接已关闭** 处理连接状态逻辑
5. 在需要时使用关闭动作断开连接

# 动作

## 连接到远程服务器

在不发送负载数据的情况下初始化远程服务器连接。

输入：

- 远程服务器 URL

## 发送数据到远程服务器

连接（或复用现有连接）并发送文本数据。

输入：

1. 远程服务器 URL
2. 数据

## 关闭远程服务器连接

按请求 ID 关闭一个连接。

输入：

- 连接请求 ID

## 关闭所有远程服务器连接

关闭当前所有处于活动状态的远程服务器连接。

# 监听器

## 远程服务器已连接

当远程服务器连接初始化时触发。

变量：

- `$$request_id`
- `$$remote_server_url`

## 远程服务器接收到数据时

当从已连接的远程服务器接收到数据时触发。

变量：

- `$$request_id`
- `$$remote_server_url`
- `$$data`

## 远程服务器连接已关闭

当远程服务器连接关闭时触发。

变量：

- `$$request_id`
- `$$remote_server_url`
- `$$intentionally_closed`
- `$$crashed`
- `$$unknown_close_reason`

# 连接行为

- 连接由 **客户端发起**
- FancyMenu 会在后台保持连接活动
- 如果连接崩溃或超时，FancyMenu 会每 10 秒重试一次
- 当崩溃的连接恢复时，FancyMenu 会记录一条恢复消息
- 未发送的出站消息会进入队列，**最大保留 30 秒**
- 队列中超过 30 秒的消息会被丢弃

# URL 模式

- `wss://` = 安全连接（TLS），推荐
- `ws://` = 未加密，适合本地测试

本地 URL 示例：

- `ws://127.0.0.1:8765`

# 最佳实践

1. 为每个后端服务使用一个稳定的 URL。
2. 针对每种使用场景保持一致的负载格式。
3. 使用备用 UI 逻辑处理已关闭/已崩溃的连接。
4. 当流程结束时使用关闭动作。
5. 在生产环境中使用 `wss://`。
