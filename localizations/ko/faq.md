# FAQ

### 문제가 있습니다. 어떤 정보를 제공해야 하나요?
가장 정확한 도움을 받으려면 가능한 한 많은 정보를 제공해 주세요:
1.  **문제에 대한 명확한 설명:** 무엇을 기대했고, 실제로는 무엇이 발생했나요?
2.  **`latest.log` 파일:** 문제 해결에 가장 중요한 파일입니다. 인스턴스의 `/logs/` 폴더에서 찾을 수 있습니다. 특별히 요청받지 않았다면 **크래시 로그는 보내지 마세요**. `latest.log`가 훨씬 유용합니다. 공유할 때는 https://gist.github.com 같은 사이트를 사용하세요.
3.  **Minecraft 버전:** (예: 1.20.1)
4.  **모드 로더와 버전:** (예: Forge 47.2.0, Fabric 0.15.7)
5.  **FancyMenu 버전:** (예: 3.5.2)
6.  **문제의 스크린샷이나 영상**도 큰 도움이 됩니다.

### 요소의 레이어 순서(다른 요소 앞/뒤로 이동)를 어떻게 바꾸나요?
*   **커스텀 vs. 커스텀:** 직접 만든 커스텀 요소들의 렌더 순서를 바꾸려면 **Layers 위젯**을 사용하세요. 메뉴 바에서 **Window -> Widgets -> Layers**로 열 수 있습니다. 여기서 요소를 계층 구조에서 위아래로 드래그할 수 있습니다. 요소를 마우스 오른쪽 버튼으로 클릭한 뒤 "Move One Layer Up/Down"을 사용할 수도 있습니다.
*   **커스텀 vs. 바닐라:** 모든 커스텀 요소를 모든 바닐라 요소 뒤에 렌더링하려면(예: 기본 버튼 뒤에 배경 이미지를 두려면), **편집기 배경을 마우스 오른쪽 버튼으로 클릭**한 다음 **"Render Custom Elements Behind Vanilla"** 옵션을 켜세요.

### 보편 버튼 템플릿에서 특정 버튼만 제외할 수 있나요?
**아니요. 템플릿 버튼에 커스텀 텍스처가 설정되어 있으면, 이 텍스처는 항상 영향을 받는 모든 요소와 공유됩니다. 개별 버튼을 제외할 수는 없습니다.**

### 버튼을 클릭했을 때 어떤 동작을 하게 하려면 어떻게 하나요?
**Action Script**를 사용하세요.
1.  편집기에서 버튼을 마우스 오른쪽 버튼으로 클릭합니다.
2.  **Edit Action Script**를 선택합니다.
3.  **Add Action**을 클릭하고 목록에서 작업을 선택합니다(예: `Open Screen or Custom GUI`, `Join Server`, `Set Variable Value`).
*   자세한 정보: [Action Scripts](https://docs.fancymenu.net/en/action-scripts)

### 완전히 새로운 메뉴 화면을 처음부터 만들 수 있나요?
네, **Custom GUIs**를 사용하면 됩니다.
1.  메뉴 바에서 **Customization -> Custom GUIs -> Manage Custom GUIs**로 이동합니다.
2.  **"New GUI"**를 클릭하고 고유한 식별자를 입력합니다.
3.  그런 다음 이 새 빈 화면을 열어 원하는 요소를 추가해 레이아웃을 만들 수 있습니다.
4.  이렇게 만든 Custom GUI는 버튼 동작으로 열 수 있습니다.
*   자세한 정보: [Custom GUIs](https://docs.fancymenu.net/en/custom-guis)

### 프리로딩을 켠 후 게임 로딩이 너무 오래 걸립니다.
이는 예상된 동작입니다. 고해상도 애니메이션이나 사운드처럼 큰 리소스를 초기 시작 시 미리 로드하면 게임 로딩 시간이 자연스럽게 늘어납니다.

### FMA 애니메이션이 RAM을 너무 많이 사용합니다!
기존 FMA 파일은 고해상도 프레임이 많이 포함되어 있으면 메모리를 많이 사용할 수 있습니다. FancyMenu 3.9.0에서는 큰 규모나 복잡한 애니메이션 텍스처에 훨씬 적합한 AFMA가 추가되었습니다. 기존 FMA 파일의 경우 애니메이션을 짧게 유지하고, 너무 큰 프레임 수나 해상도는 피하세요. 애니메이션은 전체 영상을 재생하기 위한 것이 아니라, 짧고 장식적인 반복용입니다.

### FancyMenu는 OptiFine과 함께 작동하나요?
아니요. OptiFine은 **호환되지 않으며** FancyMenu를 포함한 많은 모드를 깨뜨리는 것으로 알려져 있습니다. Sodium/Embeddium + Iris/Oculus 같은 최신 대안을 사용하는 것이 강력히 권장됩니다.
*   자세한 정보: [OptiFine Alternatives](https://docs.fancymenu.net/en/optifine-alternatives)

### 게임이 충돌합니다. 모드 충돌인지 어떻게 확인하나요?
모드 충돌 여부를 확인하는 가장 좋은 방법은 **FancyMenu와 그 의존성(Konkrete, Melody)만 설치한 상태로 게임을 실행하는 것**입니다. 더 이상 충돌이 발생하지 않는다면, 다른 모드를 조금씩 다시 추가해 보면서 충돌이 다시 발생하는 시점을 확인하면 문제를 일으키는 모드를 찾을 수 있습니다.

### 다른 모드의 버튼이 사라지거나, 편집하려고 하면 작동하지 않습니다.
대개 이는 다른 모드가 FancyMenu가 상호작용할 수 없는 비표준 방식으로 버튼을 추가한다는 뜻입니다. 이 문제는 해당 모드 개발자가 수정해야 합니다. FancyMenu는 "보이지" 않는 요소를 커스터마이즈할 수 없습니다.

### 서버에서 FancyMenu 레이아웃을 사용할 수 있나요?
FancyMenu는 클라이언트 측 모드입니다. 모든 레이아웃과 커스터마이징은 플레이어의 클라이언트에 적용됩니다. 플레이어가 보도록 강제하기 위해 서버에 레이아웃을 넣을 수는 없습니다. 하지만 모드팩의 일부로 `config/fancymenu` 폴더를 배포할 수는 있습니다. 서버에서 `/fmvariable` 또는 `/openguiscreen` 같은 명령을 사용하려면 서버에 FancyMenu(또는 Spigot 플러그인)가 설치되어 있어야 합니다.

### FancyMenu v2(구버전 MC용)와 v3의 차이점은 무엇인가요?
FancyMenu v3는 많은 새 기능, 더 안정적인 구조, 향상된 성능을 갖춘 완전한 재작성 버전입니다. V2는 오래되었고 더 이상 지원되지 않으며, 고급 플레이스홀더나 스크립팅 같은 많은 기능이 빠져 있습니다. 최신 Minecraft 버전(1.18.2+)에서는 v3 사용이 강력히 권장됩니다. V2 레이아웃은 불러올 때 v3로 자동 변환할 수 있지만, 일부는 수동 수정이 필요할 수 있습니다.

### 미리 만들어진 레이아웃과 템플릿은 어디에서 찾을 수 있나요?
FancyMenu 커뮤니티는 공식 Keksuccino's Mods Discord 서버의 `#layout-templates` 채널에서 레이아웃을 공유합니다.

### Player Entity를 다른 요소 뒤에 렌더링하려면 어떻게 하나요?
불가능합니다. Minecraft의 엔티티 렌더링 방식 때문에, Player Entity 요소는 레이어 설정과 관계없이 거의 항상 다른 2D 요소 앞에 렌더링됩니다.

### 내 Player Entity에 다리가 하나만 있습니다! 무슨 일이죠?
이것은 시각적 오류로, 플레이어 애니메이션이나 모델을 변경하는 다른 모드와의 충돌로 인해 발생했을 가능성이 큽니다. Player Entity의 Pose 설정을 확인해 다리가 실수로 회전되거나 이동되지 않았는지 살펴보세요.

### 스크립트에서 작업 사이에 지연을 어떻게 넣나요?
FancyMenu 3.9.0에서는 액션 스크립트에 **Delay**와 **Execute Later** 블록이 추가되었습니다. 대부분의 지연 작업 로직에는 이를 사용하세요. 반복되는 백그라운드 로직에는 [Schedulers](https://docs.fancymenu.net/en/schedulers)를 사용하세요.

### Create 모드의 메뉴를 커스터마이즈할 수 있나요?
아니요. FancyMenu는 Create의 복잡한 GUI와 호환되지 않는 것으로 알려져 있습니다. 충돌을 방지하기 위해 Create 화면에 대한 커스터마이징은 의도적으로 비활성화되어 있습니다.

### 왜 mod X의 버튼이 편집기에서 사라지나요?
이는 해당 모드가 바닐라가 아닌 커스텀 방식으로 버튼을 추가하기 때문입니다. FancyMenu는 이러한 요소를 "볼" 수도, 상호작용할 수도 없어서 커스터마이즈할 수 없습니다. 다른 모드의 개발자가 버튼을 추가하는 방식을 바꿔야 호환될 수 있습니다.

### 배경 이미지와 버튼 텍스처에 권장되는 해상도는 무엇인가요?
배경: 표준 1920x1080(1080p) 이미지는 훌륭한 시작점이며 대부분의 사용자에게 잘 맞게 확대/축소됩니다.
버튼: 대부분의 바닐라 버튼은 가로 150~200픽셀, 세로 20픽셀 정도입니다. 커스텀 텍스처도 이 크기에 맞추는 것이 일관성 측면에서 좋습니다.

### 플레이어가 게임 내 목표(예: 퀘스트)를 완료했을 때 자동으로 메뉴를 열거나 명령을 실행할 수 있나요?
FancyMenu 자체는 이런 게임 내 이벤트를 감지할 수 없습니다. 하지만 FTB Quests 같은 퀘스트 모드와 연동할 수 있습니다. 대부분의 퀘스트 모드는 보상으로 명령을 실행할 수 있습니다. 보상으로 `/openguiscreen` 또는 `/fmvariable` 명령을 실행하도록 설정해 메뉴와 상호작용할 수 있습니다.

### 버튼을 비활성화하거나 "회색으로" 보이게 하려면 어떻게 하나요?
Loading Requirements를 사용하여 버튼의 활성 상태를 제어할 수 있습니다.
편집기에서 버튼을 마우스 오른쪽 버튼으로 클릭한 뒤 "Active State"를 선택하세요.
버튼이 활성화되기 위해 충족해야 하는 조건을 추가합니다. 예를 들어, 버튼을 영구적으로 비활성화하려면 0이 1과 같은지 확인하는 Is Number 조건을 추가할 수 있습니다(항상 거짓).
이제 버튼은 "Inactive Background" 텍스처를 사용하고 클릭할 수 없게 됩니다.

### 스크롤 가능한 화면에서 헤더와 푸터(흙 텍스처 바)를 어떻게 제거하나요?
FancyMenu v3에서는 이를 커스터마이즈할 수 있습니다. 레이아웃 편집기에서 편집기 배경을 마우스 오른쪽 버튼으로 클릭하고 "Customize Header/Footer" 같은 옵션을 찾아보세요. 텍스처를 완전히 투명하게 설정하면 시각적으로 사실상 제거할 수 있습니다. 다만 모든 화면, 특히 오래되었거나 모드가 많이 추가된 화면에서는 작동하지 않을 수 있습니다.

### "현재 화면용" 레이아웃을 만들 수 없습니다. 버튼이 회색으로 비활성화되어 있습니다.
먼저 해당 화면의 커스터마이징을 **메뉴 바 -> Customization -> Current Screen Customizations -> Enabled로 전환**해서 활성화해야 합니다.

### 편집기에서 화면을 열었는데 요소를 하나도 커스터마이즈할 수 없습니다. 그냥 빈 화면입니다.

이 경우 실수로 **현재 화면용**이 아니라 보편 레이아웃을 만든 것일 수 있습니다.

또는 커스터마이즈하려는 화면이 스크롤 가능한 화면일 수도 있습니다. 이런 화면은 기본적으로 FancyMenu가 커스터마이즈할 수 없습니다.

세 번째 가능성은 해당 화면이 바닐라가 아닌 방식으로 요소를 추가하는 모드의 화면이라는 점입니다. 이 경우 FancyMenu가 해당 요소를 커스터마이즈할 수 없습니다.

### Text 요소에 이상한 회색 상자가 보입니다.

이 반투명(낮은 불투명도) 상자/사각형은 Text 요소의 오른쪽 또는 아래쪽 가장자리에 나타날 수 있으며, 버그가 아닙니다. 이들은 요소가 스크롤 가능하기 때문에 표시되는 Text 요소의 스크롤 그랩버입니다.

이 상자를 보이지 않게 하려면, 요소를 마우스 오른쪽 버튼으로 클릭한 뒤 스크롤을 완전히 비활성화하거나, 요소를 계속 스크롤 가능하게 유지하고 싶다면 같은 우클릭 메뉴에서 그랩버 텍스처를 완전히 투명한 것으로 설정할 수 있습니다.

### 최신 Minecraft 변경 로그를 메뉴에 어떻게 표시하나요?

Minecraft 변경 로그를 FancyMenu와 호환되는 Markdown으로 변환해 주는 훌륭한 [GitHub 프로젝트](https://github.com/ClaytonTDM/minecraft-changelogs-markdown)가 있습니다. 이를 사용하면 최신 MC 변경 로그를 메뉴에 표시할 수 있습니다! 새 변경 로그를 가져오기 위해 매일 업데이트됩니다.

예를 들어, 최신 Minecraft 변경 로그를 Text 요소에 표시하려면 **Source Mode**를 **Resource**로 설정하고 리소스 소스를 **Web**으로 설정하세요. 그런 다음 다음 URL을 소스로 사용합니다: `https://clay.is-a.dev/minecraft-changelogs-markdown/{"placeholder":"mcversion"}/fancymenu.md`

### 어떤 요소든 화면 크기에 맞게 늘리는 가장 쉬운 방법은 무엇인가요?

대부분의 요소는 우클릭 컨텍스트 메뉴에서 가로 및 세로로 늘리는 옵션이 있습니다. 이 옵션을 활성화하면 항상 화면의 전체 너비 및/또는 높이에 맞게 늘어납니다. 가로와 세로 확장은 서로 독립적으로 켜고 끌 수 있습니다.

### Text 요소 앞이나 뒤에 있을 때 버튼을 클릭하거나 슬라이더를 조작할 수 없습니다.

이는 Text 요소가 기본적으로 상호작용 가능하기 때문입니다(스크롤 그랩버를 잡거나 Markdown 하이퍼링크를 클릭할 수 있어야 하므로). 즉, 마우스 클릭과 스크롤 이벤트를 가로챕니다. 가장 좋은 방법은 버튼을 Text 요소 앞/뒤로 옮기지 않는 것이지만, 피할 수 없다면 Text 요소를 **마우스 오른쪽 버튼으로 클릭**한 뒤 **Interactable**을 **Disabled**로 설정해 상호작용하지 않게 만들 수 있습니다. 단, 이렇게 하면 Text 요소는 정적인 비상호작용 텍스트가 되므로 더 이상 스크롤하거나 하이퍼링크를 클릭할 수 없습니다.

### 화살표 키와 Tab 키로 화면을 탐색할 때 버튼과 슬라이더가 더 이상 선택/포커스되지 않게 하려면 어떻게 하나요?

버튼과 슬라이더가 탐색되지 않게 하려면 **마우스 오른쪽 버튼으로 클릭**한 뒤 **Navigable**을 **Disabled**로 설정해야 합니다. 이렇게 해도 버튼/슬라이더는 클릭할 수 있지만, 화살표/Tab 탐색으로는 더 이상 포커스를 받을 수 없습니다.

이 설정은 채팅 화면에 버튼/슬라이더를 추가하고 싶을 때도 유용합니다. 이렇게 하면 실수로 화면의 버튼/슬라이더를 선택하지 않으면서도 위쪽 화살표 키로 이전 메시지를 스크롤할 수 있습니다.

### FancyMenu의 컨텍스트 메뉴에서 있어야 할 옵션이 보이지 않습니다.

FancyMenu의 컨텍스트 메뉴(어딘가를 마우스 오른쪽 버튼으로 클릭했을 때 또는 메뉴 바와 상호작용할 때 열리는 메뉴)는 **스크롤 가능**합니다. 즉, 메뉴 위에 마우스 커서를 올린 상태에서 마우스 휠을 사용해 위아래로 스크롤할 수 있으며, 이전에는 보이지 않던 더 많은 옵션을 볼 수 있습니다.
