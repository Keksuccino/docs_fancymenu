# Заповнювачі

Заповнювачі вставляють живі значення в текст, кнопки, вимоги та інші підтримувані поля.

# Загальна інформація

## Базовий синтаксис
Заповнювачі у FancyMenu використовують JSON-подібний синтаксис:
```
{"placeholder":"modversion","values":{"modid":"fancymenu"}}
```

Наприклад, щоб відобразити ім’я гравця:
```
{"placeholder":"playername"}
```

## Вкладені заповнювачі
Ви можете використовувати один заповнювач всередині значення іншого заповнювача.

Приклад вкладених заповнювачів:
```
{"placeholder":"calc","values":{"decimal":"true","expression":"{"placeholder":"maxram"} / 1024"}}
```
Цей приклад бере максимальне значення RAM і ділить його на 1024, щоб перетворити з МБ у ГБ.

> [!IMPORTANT]
> Це синтаксис FancyMenu, а не JSON. Вкладені заповнювачі використовують саме той неекранований формат, що показано вище, тому JSON-форматери відхилять або перепишуть їх. Імена заповнювачів чутливі до регістру; неправильні або невідомі заповнювачі залишаються видимими як текст і записуються в журнал.

# Використання заповнювачів

Більшість елементів, що мають поля введення тексту, підтримують заповнювачі. Ви можете побачити, чи підтримує текстове поле заповнювачі, під час його редагування. Якщо під час редагування тексту відкривається повноекранний **редактор тексту**, він підтримує заповнювачі.

Щоб знайти **список усіх заповнювачів**, просто натисніть кнопку **Заповнювачі** у **правому верхньому куті** **редактора тексту**.

Угорі списку заповнювачів є **рядок пошуку**, який дає змогу шукати заповнювачі.

Натискання на заповнювач у списку заповнювачів вставить його в текстовий вміст.

# Заповнювачі детально

У цьому розділі перелічено вбудовані заповнювачі FancyMenu.

## Недоступні результати

Результат заповнювача завжди є текстом. Коли дані недоступні, результат залежить від заповнювача: поширені варіанти — порожній рядок, `0`, `0.0`, `00:00`, `false`, `UNKNOWN` або `ERROR`. Елементи з конкретним запасним значенням вказують його безпосередньо; перевіряйте запасне значення перед використанням залежного від середовища виводу у [вимозі](./conditions), шляху, команді або URL.

## Останній світ або сервер (`last_world_server`)

**Призначення:** Повертає інформацію про останній відкритий світ або сервер.

**Значення:** `type`, `full_world_path`

**Приклад:**

```
{"placeholder":"last_world_server","values":{"type":"both","full_world_path":"true"}}
```
Параметри:
- `type`: Визначає, який тип інформації повертати
  - `"both"`: Повертає останній відкритий світ або сервер (за замовчуванням)
  - `"server"`: Повертає лише якщо останнім був сервер
  - `"world"`: Повертає лише якщо останнім був світ
- `full_world_path`: Керує тим, як відображаються шляхи до світу
  - `"true"`: Повертає повний шлях до світу (за замовчуванням)
  - `"false"`: Повертає лише назву світу без шляху (не впливає на сервери)

Приклади:
- Сервер: `mc.hypixel.net`
- Світ із повним шляхом: `saves/New World`
- Світ без повного шляху: `New World`

## Калькулятор (`calc`)

**Призначення:** Заповнювач калькулятора — це потужний інструмент, який дає змогу виконувати математичні обчислення у ваших макетах. Він підтримує широкий спектр математичних операцій і може працювати як із десятковими, так і з цілими числами.

**Значення:** `decimal`, `expression`

### Базовий синтаксис

**Приклад:**

```
{"placeholder":"calc","values":{"decimal":"true/false","expression":"your_expression"}}
```

Калькулятор має два основні параметри:
- `decimal`: Визначає, чи має результат містити десяткові знаки (`true`), чи бути округленим до цілих (`false`)
- `expression`: Математичний вираз для обчислення

### Підтримувані операції
Калькулятор підтримує такі математичні операції:
- Базова арифметика: `+` (додавання), `-` (віднімання), `*` (множення), `/` (ділення)
- Дужки: `( )` для групування операцій
- Степінь: `^` для піднесення до степеня
- Квадратний корінь: `sqrt()`
- Тригонометричні функції: `sin()`, `cos()`, `tan()`
- Математичні константи: `pi`, `e`
- Абсолютне значення: `abs()`
- Логарифми: `log()`, `ln()`

## Випадковий текст (`randomtext`)

**Призначення:** Повертає випадковий рядок із текстового файлу, URL або безпосереднього звичайного тексту. Текст змінюється через задані інтервали. Вміст файлів і URL оновлюється приблизно кожні 30 секунд; звичайний текст зберігається в кеші, оскільки його не потрібно перезавантажувати.

**Значення:** `source`, `interval`

У значеннях заповнювача `/config/...` означає `<game-directory>/config/...`; це не шлях від кореня файлової системи. Див. [Ресурси](./resources#local-resources).

**Приклад:**

```
{"placeholder":"randomtext","values":{"source":"/config/fancymenu/assets/<file_name.txt>","interval":"10"}}
```
Параметри:
- `source`: Джерело текстових рядків (замінює старий параметр `path`)
  - Шлях до файлу: `/config/fancymenu/assets/quotes.txt`
  - URL: `https://example.com/quotes.txt`
  - Звичайний текст: `Line 1\nLine 2\nLine 3`
- `interval`: Час у секундах між змінами тексту

Тепер заповнювач підтримує три типи джерел:
1. **Локальні файли**: Текстові файли з вашого каталогу гри
   ```
   {"placeholder":"randomtext","values":{"source":"/config/fancymenu/assets/quotes.txt","interval":"10"}}
   ```
2. **URL**: Віддалені текстові файли з інтернету
   ```
   {"placeholder":"randomtext","values":{"source":"https://example.com/quotes.txt","interval":"10"}}
   ```
3. **Звичайний текст**: Прямий введений текст із рядками, розділеними `\n`
   ```
   {"placeholder":"randomtext","values":{"source":"First line\nSecond line\nThird line","interval":"5"}}
   ```

Примітка: Старі заповнювачі, які використовують `path` замість `source`, і надалі працюватимуть.

## Парсер JSON (`json`)

**Призначення:** Парсить JSON-дані з файлу, URL або безпосереднього JSON-вмісту та витягує значення за допомогою JSON path-виразів.

**Значення:** `source`, `json_path`

**Приклад:**

```
{"placeholder":"json","values":{"source":"path_or_link_or_json_content","json_path":"$.some.json.path"}}
```
Параметри:
- `source`: Джерело JSON-даних
  - Шлях до файлу: `/config/fancymenu/assets/data.json`
  - URL: `https://api.example.com/data.json`
  - Безпосередній JSON: `{"name":"Steve","level":42}`
- `json_path`: JSON path-вираз для витягування даних

Тепер заповнювач підтримує три типи джерел:
1. **Локальні файли**: JSON-файли з вашого каталогу гри
   ```
   {"placeholder":"json","values":{"source":"/config/fancymenu/assets/playerdata.json","json_path":"$.player.name"}}
   ```
2. **URL**: Віддалені JSON-дані з API або вебсервісів
   ```
   {"placeholder":"json","values":{"source":"https://api.minecraft.com/server/status","json_path":"$.online"}}
   ```
3. **Безпосередній JSON**: Вбудований JSON-вміст
   ```
   {"placeholder":"json","values":{"source":"{"name":"Steve","score":42,"rank":"Diamond"}","json_path":"$.rank"}}
   ```

Приклади JSON-шляхів:
- `$.name` - Отримує поле "name" з кореня
- `$.player.level` - Отримує вкладене поле "level" всередині "player"
- `$.items[0].id` - Отримує "id" першого елемента в масиві
- `$.scores.*` - Отримує всі значення з об’єкта "scores"

## Текст файлу (`file_text`)

**Призначення:** Повертає текстові рядки з файлу або URL. Може повертати всі рядки або лише останні X рядків.

**Значення:** `path_or_url`, `mode`, `separator`, `last_lines`

**Приклад:**

```
{"placeholder":"file_text","values":{"path_or_url":"/config/fancymenu/assets/some_file.txt","mode":"all","separator":"\n","last_lines":"1"}}
```
Параметри:
- `path_or_url`: Шлях до файлу або URL для читання
- `mode`: Або `"all"` (повертає всі рядки), або `"last"` (повертає лише останні X рядків)
- `separator`: Текст між рядками (за замовчуванням: `"\n"`)
- `last_lines`: Кількість рядків, які повертати, коли `mode` дорівнює `"last"` (за замовчуванням: `"1"`)

**Вивід:**

```text
Second line
```

**Призначення:** Замінює текст у рядку за допомогою буквального тексту або регулярних виразів.

**Значення:** `text`, `search`, `replacement`, `use_regex`, `replace_all`

**Приклад:**

## Отримати NBT-дані (`nbt_data_get`)

**Призначення:** Отримує NBT-дані на клієнті (подібно до команди `/data get`). Використовуйте серверну версію `nbt_data_get_server`, коли ви підключені до сервера і вам потрібні достовірні серверні значення.

**Значення:** `source_type`, `entity_selector`, `nbt_path`, `scale`, `return_type`

**Приклад:**

```
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"foodLevel","scale":"1.0","return_type":"value"}}
```
Параметри:
- `source_type`: Або `"entity"`, або `"block"`
- `entity_selector`: Селектор сутності, наприклад `@s`, `@p`, `@e`, або UUID/ім’я (для сутностей)
- `block_pos`: Позиція блоку у форматі `"x y z"` (для блоків)
- `nbt_path`: Шлях NBT для отримання
- `scale`: Необов’язковий коефіцієнт масштабування для числових значень (за замовчуванням: `"1.0"`)
- `return_type`: Як повертати дані:
  - `"value"`: За замовчуванням, повертає значення (з можливим масштабуванням для чисел)
  - `"string"`: Повертає фактичні NBT-дані як рядок
  - `"snbt"`: Повертає як SNBT (форматовані NBT-дані)
  - `"json"`: Повертає як JSON-форматований компонент (для compound-тегів)

**Вивід:** `20` (для рівня голоду)

# Найкращі практики

1. **Кешуйте дорогі операції**: Деякі заповнювачі (наприклад, ті, що читають системну інформацію) можуть бути ресурсоємними. Подумайте про використання змінних для збереження їхніх значень, якщо вам потрібно використовувати їх багато разів.

2. **Використовуйте правильні налаштування десяткових знаків**: Під час роботи з обчисленнями використовуйте параметр `decimal` належним чином. Встановлюйте `false`, коли потрібні цілі числа, і `true`, коли потрібні точні десяткові значення.

3. **Обробляйте відсутні значення**: Завжди враховуйте, що має статися, якщо заповнювач не повертає значення. У таких випадках варто вказувати значення за замовчуванням.

4. **Тестуйте продуктивність**: Коли використовуєте багато заповнювачів або складні вкладені структури, перевіряйте вплив на продуктивність, особливо на слабших системах.

5. **Використовуйте розширене масштабування/позиціювання**: Для динамічних елементів інтерфейсу поєднуйте заповнювачі з розширеним масштабуванням і позиціюванням, щоб створювати адаптивні макети.

6. **Поєднуйте зі змінними**: Використовуйте заповнювачі разом зі змінними для ще більш динамічного вмісту, який можна оновлювати за допомогою дій.

# Поширені проблеми та рішення

## Заповнювач не оновлюється
Якщо значення заповнювача не оновлюється так, як очікується, перевірте:
- Чи правильно відформатований заповнювач
- Чи використовуєте ви правильний регістр для ідентифікаторів заповнювачів
- Чи потрібні заповнювачу певні умови для оновлення

## Вкладені заповнювачі не працюють
Під час вкладення заповнювачів:
- Переконайтеся, що лапки екрановані належним чином
- Перевірте, що кожен вкладений заповнювач є коректним сам по собі

## Проблеми з продуктивністю
Якщо ви помічаєте проблеми з продуктивністю:
- Зменште кількість заповнювачів
- Уникайте зайвого вкладення
- Подумайте про використання змінних для часто використовуваних значень
- Використовуйте відповідний заповнювач для своїх потреб (наприклад, не використовуйте заповнювачі реального часу, якщо достатньо статичних значень)
