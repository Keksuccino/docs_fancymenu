# API шейдерів GLSL у FancyMenu

У цьому документі описано середовище виконання GLSL, яке FancyMenu використовує для:

- фонів меню `GLSL`
- елементів `GLSL`
- декоративних накладок `GLSL`

Тут розглянуто режими компіляції, маршрутизацію кількох проходів, підтримувані uniform-змінні та практичні прийоми написання шейдерів.

## 1. Огляд середовища виконання

FancyMenu рендерить шейдери за допомогою внутрішнього конвеєра OpenGL (`#version 150`) і підтримує:

- шейдери з одним проходом (лише прохід `Image`)
- шейдери з кількома проходами (`Buffer A` / `B` / `C` / `D` + `Image`)
- точки входу у стилі Shadertoy (`mainImage`)
- безпосередні точки входу фрагментного шейдера (`main`)

Вихідний код шейдерів задається вбудованим текстом:

- `Shader Source` (прохід Image, потрібен для рендерингу)
- `Buffer A Source` (необов’язково)
- `Buffer B Source` (необов’язково)
- `Buffer C Source` (необов’язково)
- `Buffer D Source` (необов’язково)

Якщо джерело Image порожнє, рендеринг завершується помилкою «no source».

## 2. Режими компіляції

FancyMenu підтримує три режими компіляції:

- `Auto`
- `Direct Fragment`
- `Shadertoy`

### 2.1 Режим Shadertoy

Очікувана точка входу:

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord)
```

FancyMenu обгортає її у `main()` і передає координати в межах локальної області:

```glsl
mainImage(fmColor_FancyMenu, gl_FragCoord.xy - fmAreaOffset);
```

Обгортка множить вихідну альфа-складову на `fmOpacity`.

### 2.2 Режим Direct

Очікувана точка входу:

```glsl
void main()
```

Особливості сумісності:

- Виконується спроба скомпілювати варіант із підтримкою `gl_FragColor`.
- Також виконується спроба скомпілювати варіант без такої підтримки (для сучасних шейдерів з явним `out vec4`).

У режимі Direct значення `fmOpacity` автоматично не застосовується до вихідного результату. За потреби застосуйте його вручну.

### 2.3 Режим Auto

Auto по черзі пробує сумісні варіанти (Shadertoy/Direct) і використовує перший, який компілюється.

## 3. Попередня обробка вихідного коду та вбудовані макроси

Перед компіляцією FancyMenu нормалізує вихідний код:

- видаляє BOM UTF-8
- перетворює CRLF/CR на LF
- видаляє рядки `#version ...`
- видаляє рядки `precision ...;`

Преамбула, яку додає середовище виконання, містить:

- `#version 150`
- `in vec2 fmUv_FancyMenu` (UV-координати на весь екран у діапазоні `[0,1]`, початок координат унизу зліва)
- `#define iGlobalTime iTime`
- `#define texture2D texture`
- `#define textureCube texture`

Примітка:

- Якщо у вихідному коді вже оголошено відому uniform-змінну (наприклад, `iTime`), FancyMenu не додає її повторне оголошення.
- Водночас FancyMenu намагається передавати значення цій змінній під час виконання.
- Тут `textureCube` є лише макросом-псевдонімом; `iChannel0..3` — це uniform-змінні типу `sampler2D`.

## 4. Система проходів (Image + Buffer A-D)

У FancyMenu є 5 слотів проходів:

- `Buffer A`
- `Buffer B`
- `Buffer C`
- `Buffer D`
- `Image` (фінальний прохід, що виводиться на екран)

Поведінка:

- Буферні проходи виконуються лише тоді, коли їхнє джерело не порожнє.
- Для рендерингу результату має бути задано прохід Image.
- Буфери рендеряться у текстури з рухомою комою (`GL_RGBA16F`), а потім використовують почергову зміну буферів (текстури читання/запису міняються місцями кожного кадру).

### 4.1 Маршрутизація каналів для кожного проходу

У кожному проході можна налаштувати маршрутизацію для `iChannel0..3`. Для кожного каналу можна вибрати:

- `None`
- `Resource 0`
- `Resource 1`
- `Resource 2`
- `Resource 3`
- `Buffer A`
- `Buffer B`
- `Buffer C`
- `Buffer D`

Канали ресурсів беруть дані з налаштувань `iChannel# Resource`.

Значення за замовчуванням:

- для всіх маршрутів `iChannel` за замовчуванням вибрано `None`
- буферні проходи неактивні, доки джерело відповідного буфера не стане непорожнім

Важливо:

- Якщо канал спрямовано до того самого буферного проходу (зворотний зв’язок), він зчитує дані попереднього кадру (текстуру читання в схемі почергової зміни буферів).
- Якщо маршрутизоване джерело відсутнє або неактивне, прив’язується резервна текстура, а значення `iChannelResolution[n].z` стає `0.0`.

## 5. Координати та семантика областей

Шейдери виконуються в прямокутній області:

- фон меню: область на весь екран
- елемент GLSL: прямокутна область елемента

Система координат:

- Uniform-змінні пікселів задаються в локальних координатах області.
- Початок координат пікселів, переданих шейдеру, розташований унизу зліва.
- Координати миші не обмежуються: якщо курсор поза областю, значення можуть виходити за її межі.

Спеціальні поля:

- `fmAreaOffset`: положення нижнього лівого кута області в екранних координатах пікселів
- `fmAreaTopLeft`: положення верхнього лівого кута області в екранних координатах пікселів
- `fmAreaSize`: розмір області в пікселях

## 6. Довідник API uniform-змінних

Усі наведені нижче uniform-змінні доступні шейдерам фону й елементів.

## 6.1 Uniform-змінні, сумісні з Shadertoy

| Uniform-змінна | Тип | Значення |

| `iResolution` | `vec3` | `(areaWidthPx, areaHeightPx, 1.0)` |
| `iTime` | `float` | Накопичений час роботи шейдера у секундах |
| `iTimeDelta` | `float` | Час між останнім рендерингом і поточним, залежить від заморожування/масштабу часу |
| `iFrameRate` | `float` | FPS Minecraft; якщо недоступні, використовуються FPS середовища виконання |
| `iFrame` | `int` | Лічильник кадрів для поточного середовища виконання |
| `iMouse` | `vec4` | Докладніше див. нижче |
| `iDate` | `vec4` | `(рік, місяць, день, секунди_доби_з_дробовою_частиною)` |
| `iSampleRate` | `float` | Стала `44100.0` |
| `iChannelTime[4]` | `float[4]` | Наразі для всіх каналів дорівнює `iTime` |
| `iChannelResolution[4]` | `vec3[4]` | `(ширина, висота, прапорець_доступності)` для кожного каналу |
| `iChannel0..3` | `sampler2D` | Маршрутизовані текстури на вході |

### Докладніше про `iMouse`

`iMouse = vec4(x, y, z, w)`

- `x`, `y`: поточне положення миші в локальних координатах області (пікселі) або зафіксоване значення, якщо ввімкнено відповідний перемикач
- `z`, `w`: координати початку натискання лівої кнопки миші
  - додатні, поки ліва кнопка миші утримується
  - від’ємні після її відпускання

Поведінка залежно від перемикача:

- `Update iMouse Position Only While Holding LMB = Off`:
  - `iMouse.xy` постійно оновлюється
- `... = On`:
  - `iMouse.xy` оновлюється лише під час утримання лівої кнопки миші, а потім зберігає останнє зафіксоване положення

Значення за замовчуванням:

- `Off` (постійне оновлення)

## 6.3 API uniform-змінних FancyMenu

Змінні FancyMenu безпосередньо доступні як uniform-змінні середовища виконання (для шейдерів фону, елементів і декоративних накладок). Зміна їхніх значень не потребує повторної компіляції шейдера.

### Іменування

Для кожної змінної `<name>` FancyMenu надає:

- `fmVarFloat_<name>`
- `fmVarInt_<name>`
- `fmVarBool_<name>`
- `fmVarVec2_<name>`
- `fmVarVec3_<name>`
- `fmVarVec4_<name>`
- `fmVarExists_<name>` (`1` = змінна існує зараз, `0` = відсутня/видалена)

Правила нормалізації суфікса uniform-змінної `<name>`:

- дозволені символи: `[A-Za-z0-9_]`
- усі інші символи замінюються на `_`
- якщо перший символ — цифра, на початку додається `_`

Приклади:

- змінна `player_hp` -> суфікс `player_hp`
- змінна `player-hp` -> суфікс `player_hp`
- змінна `2nd_phase` -> суфікс `_2nd_phase`

Важливо:

- ці динамічні uniform-змінні не оголошуються в коді шейдера автоматично (оголошуйте вручну ті, які використовуєте)
- уникайте назв змінних, які після нормалізації мають однаковий суфікс, оскільки вони відповідатимуть однаковій назві uniform-змінної GLSL

### Перетворення значень

Для текстового значення змінної `v`:

- `fmVarFloat_*`: розібране значення типу float (якщо розбір не вдався, використовується `0.0`)
- `fmVarInt_*`: розібране значення типу int (якщо розбір не вдався, використовується `0`)
- `fmVarBool_*`: логічна/цілочисельна інтерпретація (`true/yes/on/enabled` => `1`, `false/no/off/disabled` => `0`, інакше ненульове числове значення => `1`)
- для векторів приймаються роздільники: пробіли, `,`, `;`, `|`
  - `fmVarVec2_*`: перші 2 розібрані компоненти
  - `fmVarVec3_*`: перші 3 розібрані компоненти
  - `fmVarVec4_*`: перші 4 розібрані компоненти
  - якщо компонентів менше, останній розібраний компонент повторюється для відсутніх значень
  - якщо числових компонентів немає, для всіх компонентів вектора використовується скалярне значення за замовчуванням

[Спискові змінні](/variables#text-and-list-variables) повертають кількість елементів замість текстового значення:

- `fmVarFloat_*` і `fmVarInt_*`: кількість елементів, наприклад `3` для списку з 3 елементів
- `fmVarBool_*`: `1`, якщо список містить елементи, `0`, якщо він порожній
- `fmVarVec2_*`, `fmVarVec3_*` і `fmVarVec4_*`: кількість елементів для кожної компоненти

Якщо змінну видалено:

- `fmVarExists_*` стає рівним `0`
- усі відповідні значення `fmVar*_*` скидаються до `0`

### Приклад оголошення та використання

```glsl
uniform float fmVarFloat_player_hp;
uniform int fmVarBool_is_boss_phase;
uniform vec3 fmVarVec3_theme_color;
uniform int fmVarExists_player_hp;

void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;

    float hp = clamp(fmVarFloat_player_hp / 100.0, 0.0, 1.0);
    vec3 theme = fmVarVec3_theme_color;
    float boss = float(fmVarBool_is_boss_phase);

    vec3 col = mix(theme * 0.25, theme, hp);
    col += vec3(0.2, 0.0, 0.0) * boss;

    if (fmVarExists_player_hp == 0) {
        col = vec3(0.15);
    }

    fragColor = vec4(col, 1.0);
}
```

## 7. Модель відстеження введення

FancyMenu відстежує введення глобально й зберігає його стан для кожного рендерингу:

- рух/перетягування миші
- натискання/відпускання кнопок миші
- прокручування
- натискання/відпускання/повтор клавіш
- введення символів

Надійна обробка миші:

- Середовище виконання щокадру звіряє стани кнопок із даними опитування GLFW, щоб запобігти зависанню кнопок у натиснутому стані.

Якщо параметр `Pass Input Events To Shader` вимкнено:

- uniform-змінні введення щокадру скидаються до нейтральних значень
- лічильники та події обнуляються в даних, видимих шейдеру

## 8. Відомості про текстурні входи

Канали ресурсів (`iChannel# Resource`) очікують двовимірні текстури.

Стан текстури для кожного каналу:

- доступний ресурс: прив’язана текстура, реальна ширина/висота, `iChannelResolution[n].z = 1.0`
- ресурс відсутній/неактивний/None: резервна текстура, `iChannelResolution[n].xyz = (0,0,0)`

Текстури буферів:

- внутрішній формат: `RGBA16F` (з рухомою комою)
- фільтрація: лінійна
- обгортання: затискання до країв

Цей формат підходить для даних із кількома проходами (зокрема для значень за межами `[0,1]`).

## 9. Примітки щодо рендерингу та змішування

- Буферні проходи рендеряться поза екраном, без змішування.
- Для композиції у фінальному проході Image використовується параметр `Enable Blending`.
- Обгортка Shadertoy автоматично застосовує `fmOpacity` до альфа-складової.
- За потреби шейдери Direct мають застосовувати `fmOpacity` вручну.

## 10. Практичні шаблони

## 10.1 Мінімальний шейдер у стилі Shadertoy

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;
    vec3 col = vec3(uv, 0.5 + 0.5 * sin(iTime));
    fragColor = vec4(col, 1.0);
}
```

## 10.2 Мінімальний безпосередній фрагментний шейдер

```glsl
out vec4 FragColor;

void main() {
    vec2 uv = gl_FragCoord.xy - fmAreaOffset;
    uv /= iResolution.xy;

    vec3 col = vec3(uv.x, uv.y, 0.5 + 0.5 * sin(iTime));
    FragColor = vec4(col, fmOpacity);
}
```

## 10.3 Мінімальний зворотний зв’язок із кількома проходами

### Джерело Buffer A

Маршрут: `Buffer A iChannel0 Input -> Buffer A`

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;
    vec4 prev = texture(iChannel0, uv);
    vec4 seed = vec4(uv, 0.0, 1.0);
    fragColor = mix(prev, seed, 0.02);
}
```

### Джерело Image

Маршрут: `Image iChannel0 Input -> Buffer A`

```glsl
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = fragCoord / iResolution.xy;
    fragColor = texture(iChannel0, uv);
}
```

## 11. Перелік перевірок для усунення неполадок

- Немає виводу:
  - перевірте, чи не порожнє джерело Image
  - перевірте, чи відповідає режим компіляції точці входу (`mainImage` або `main`)
- Фіолетові/недійсні текстури:
  - перевірте прив’язки ресурсів і маршрутизацію каналів
  - перевірте `iChannelResolution[n].z` (`0.0` означає, що канал недійсний/недоступний)
- Неправильні координати в шейдері Direct:
  - використовуйте `gl_FragCoord.xy - fmAreaOffset` для локальних координат області
- Неправильна поведінка під час перетягування:
  - скористайтеся перемикачем `Update iMouse Position Only While Holding LMB`
- У шейдері Direct не застосовується непрозорість:
  - самостійно помножте альфа-складову на `fmOpacity`
