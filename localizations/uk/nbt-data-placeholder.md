# Плейсхолдери NBT-даних

FancyMenu надає два NBT-плейсхолдери:

| Плейсхолдер | Виконується на | Доступні дані |
|---|---|---|
| `nbt_data_get` | Клієнт | Сутності та блок-ентіті, видимі клієнту |
| `nbt_data_get_server` | Сервер | Цілі ванільної команди `/data get`; потребує FancyMenu на сервері |

# Плейсхолдер на боці клієнта

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health"}}
```

## Значення

| Значення | Обов’язково | Опис |
|---|---|---|
| `source_type` | Так | `entity` або `block` |
| `entity_selector` | Для сутностей | Селектор на боці клієнта, UUID або точна назва сутності |
| `block_pos` | Для блоків | Три абсолютні цілі координати, наприклад `100 64 -200` |
| `nbt_path` | Так | Шлях NBT, наприклад `Health`, `Pos[0]` або `Inventory[0].id` |
| `scale` | Ні | Множить числові результати `value`; за замовчуванням `1.0` |
| `return_type` | Ні | `value`, `string`, `snbt` або `json`; за замовчуванням `value` |

Координати блоків на боці клієнта не підтримують `~` або `^`.

## Селектори сутностей на клієнті

| Селектор | Початкові цілі | Типовий порядок |
|---|---|---|
| `@s` | Локальний гравець | Самець | 
| `@p` | Гравці | Найближчі |
| `@a` | Гравці | Порядок ітерації клієнта |
| `@r` | Гравці | Випадковий |
| `@e` | Усі сутності, видимі клієнту | Порядок ітерації клієнта |

`@e` не вибирає найближчу сутність, якщо не додати `sort=nearest`. Також підтримується прямий пошук за UUID і точною назвою сутності.

Підтримувані параметри селектора:

| Параметр | Опис |
|---|---|
| `type` | ID сутності; додайте `!` для виключення |
| `name` | Точна відображувана назва; додайте `!` для виключення |
| `tag` | Тег сутності; додайте `!` для виключення |
| `limit` | Додатній ліміт результатів |
| `sort` | `nearest`, `furthest`, `random` або `arbitrary` |
| `distance` | Діапазон відстані ванілі, наприклад `..10` або `5..20` |
| `x`, `y`, `z` | Початок пошуку; приймає абсолютні значення та зміщення `~` |
| `dx`, `dy`, `dz` | Розмір області пошуку від початку |

Локальні координати `^` та інші ванільні параметри селектора не підтримуються клієнтським плейсхолдером.

Приклад:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@e[type=minecraft:zombie,sort=nearest,limit=1,distance=..20]","nbt_path":"Health"}}
```

## Типи повернення

| Тип | Результат |
|---|---|
| `value` | Числові теги форматуються як числа та використовують `scale`; рядкові теги повертають свій текст; інші теги повертають текст у стилі SNBT |
| `string` | Повертає рядкове значення тега або порожній рядок, якщо тег не має рядкового значення |
| `snbt` | Повертає SNBT-представлення тега |
| `json` | Лише для compound-тегів: повертає серіалізований текстовий компонент Minecraft із красивим виводом NBT |

Режим `json` на боці клієнта не є прямим перетворенням NBT у JSON.

## Приклади

Голод гравця:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"foodLevel"}}
```

ID предмета в першому слоті панелі швидкого доступу:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Inventory[{Slot:0b}].id","return_type":"string"}}
```

Кількість предметів у блок-ентіті:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"block","block_pos":"100 64 -200","nbt_path":"Items[0].count"}}
```

# Плейсхолдер на боці сервера

`nbt_data_get_server` відповідає поведінці серверної команди `/data get` і підтримує:

- Повні серверні селектори сутностей.
- Цілі-блоки з абсолютними, відносними (`~`) або локальними (`^`) координатами.
- Командне сховище через `source_type:"storage"`.

```text
{"placeholder":"nbt_data_get_server","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health","return_type":"value"}}
```

Плейсхолдер повертає порожнє значення, доки не надійде відповідь від сервера. Відповіді короткочасно кешуються, щоб уникнути надмірної кількості запитів.

# Пошук шляхів NBT

Використайте відповідну команду без NBT-шляху, щоб переглянути доступні дані:

```text
/data get entity @s
/data get block 100 64 -200
```

Результати на боці клієнта обмежені даними, синхронізованими з клієнтом. Неправильні цілі або шляхи повертають порожній рядок і записують деталі в `logs/latest.log`.
