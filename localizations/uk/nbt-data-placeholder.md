# Отримання даних NBT

Ці плейсхолдери доступні у FancyMenu v3.8.0+.

Плейсхолдери **Client NBT Data Get** і **Server NBT Data Get** дозволяють отримувати дані NBT (Named Binary Tag) з сутностей і блоків у Minecraft, подібно до команди `/data get`. Це надзвичайно корисно для створення динамічних макетів, які реагують на стан гри, статистику гравця або умови світу.

> Цей плейсхолдер особливо потужний для модифікованого геймплею, оскільки може отримувати доступ до користувацьких NBT-даних, які моди додають до сутностей і гравців. Незалежно від того, чи граєте ви з магічними модами, що додають системи мани, RPG-модами з власними характеристиками або технологічними модами зі значеннями енергії, ви можете відображати ці модифіковані значення у своїх UI-макетах.
{.is-info}

## Огляд

Ці плейсхолдери витягують певні значення зі структур даних NBT за допомогою NBT-шляхів. Ви можете отримувати здоров'я гравця, рівень голоду, предмети інвентарю, стани блоків, модифіковані атрибути на кшталт мани або енергії та багато іншого.

Клієнтська версія плейсхолдера має велику перевагу: вона працює повністю на стороні клієнта, тож FancyMenu не потрібен на сервері, але це також робить її набагато обмеженішою, оскільки не все, що пов'язано з даними NBT, завжди видно всім клієнтам.

Серверна версія вимагає, щоб FancyMenu був встановлений на сервері, але натомість вона має **повну підтримку** практично **всього**, що зберігається як NBT.

Ця сторінка зосереджена на клієнтській версії (`nbt_data_get`), але все працює дуже схоже і для серверної версії (`nbt_data_get_server`).

## Синтаксис плейсхолдера

```
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health"}}
```

## Обов'язкові значення

| Значення | Опис | Варіанти |
|-------|-------------|---------|
| `source_type` | Тип джерела даних | `entity` або `block` |
| `nbt_path` | Шлях NBT для запиту | напр. `Health`, `foodLevel`, `Pos[0]`, `Inventory[0].id` |

## Умовні значення

Залежно від `source_type`, вам знадобиться одне з наведених нижче:

| Значення | Потрібно, коли | Опис | Формат |
|-------|--------------|-------------|--------|
| `entity_selector` | source_type дорівнює `entity` | Вибирає, до якої сутності звертатися | `@s` (себе), `@p` (найближчий гравець), `@e` (найближча сутність), UUID або ім'я сутності |
| `block_pos` | source_type дорівнює `block` | Координати блоку | `x y z` (наприклад, `100 64 -200`) |

## Додаткові значення

| Значення | Опис | Типове значення | Варіанти |
|-------|-------------|---------|---------|
| `scale` | Множник для числових значень | `1.0` | Будь-яке десяткове число |
| `return_type` | Як форматувати повернуті дані | `value` | `value` (числове/розмір), `string` (текст), `snbt` (форматований NBT), `json` (формат JSON) |

## Пояснення типів повернення

- **`value`** — повертає числові значення або розміри (за замовчуванням)
  - Для чисел: повертає число (за потреби масштабоване)
  - Для рядків: повертає довжину рядка
  - Для списків/масивів: повертає кількість елементів
  - Для compound: повертає кількість тегів

- **`string`** — повертає фактичне рядкове значення даних NBT

- **`snbt`** — повертає дані у форматі SNBT (Stringified NBT)

- **`json`** — повертає дані у форматі JSON (лише для compound-тегів)

## Приклади

### Отримати здоров'я гравця
```json
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health"}}
```

### Отримати рівень голоду гравця
```json
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"foodLevel"}}
```

### Отримати X-координату гравця
```json
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Pos[0]"}}
```

### Отримати предмет у першому слоті гарячої панелі
```json
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Inventory[{Slot:0b}].id","return_type":"string"}}
```

### Отримати дані блоку в певній позиції
```json
{"placeholder":"nbt_data_get","values":{"source_type":"block","block_pos":"100 64 -200","nbt_path":"Items[0].Count"}}
```

### Отримати масштабований відсоток здоров'я (Health * 5)
```json
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health","scale":"5"}}
```

## Як знайти доступні NBT-шляхи

### Спосіб 1: Використання команди `/data get` (рекомендовано)

Найпростіший спосіб дізнатися доступні NBT-шляхи — використати команду `/data get` у грі без указання шляху:

1. **Для сутностей:** `/data get entity @p`
2. **Для блоків:** `/data get block <x> <y> <z>`

Це покаже всі доступні дані NBT для цієї цілі та дасть вам точні шляхи, які можна використовувати.

#### Розуміння виводу

Коли ви виконуєте `/data get entity @p`, побачите вивід, подібний до цього:

```
Player616 has the following entity data: {Brain: {memories: {}}, 
HurtByTimestamp: 0, SleepTimer: 0s, Invulnerable: 0b, FallFlying: 
0b, PortalCooldown: 0, AbsorptionAmount: 0.0f, abilities: 
{invulnerable: 1b, mayfly: 1b, instabuild: 1b, walkSpeed: 0.1f, 
mayBuild: 1b, flying: 1b, flySpeed: 0.05f}, FallDistance: 0.0f, 
recipeBook: {recipes: ["minecraft:crafting_table"]}, 
DeathTime: 0s, XpSeed: -380875747, XpTotal: 0, UUID: [I; 1379890089, -1732753738, 
-2135065633, -718799804], playerGameType: 1, seenCredits: 
0b, Motion: [0.0d, 0.0d, 0.0d], Health: 20.0f, foodSaturationLevel: 
5.0f, ...}
```

Щоб витягнути коректний шлях із цього виводу:

1. **Прості значення** — використовуйте назву ключа безпосередньо:
   - `Health: 20.0f` → Шлях: `Health`
   - Приклад: `{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health"}}`

2. **Вкладені значення** — використовуйте крапкову нотацію для доступу до вкладених даних:
   - `abilities: {walkSpeed: 0.1f}` → Шлях: `abilities.walkSpeed`
   - Приклад: `{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"abilities.walkSpeed"}}`

3. **Масиви** — використовуйте дужки з індексом:
   - `Motion: [0.0d, 0.0d, 0.0d]` → Шлях для руху по Y: `Motion[1]`
   - Приклад: `{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Motion[1]"}}`

### Спосіб 2: Мод NBT Autocomplete

Для простішого пошуку NBT-шляхів розгляньте встановлення мода **NBT Autocomplete**:
- Доступний для Fabric і Forge (Minecraft 1.21.x)
- Надає підказки автодоповнення в грі під час введення команд
- Показує доступні назви тегів і типи
- [Modrinth](https://modrinth.com/mod/nbt-autocomplete) | [CurseForge](https://www.curseforge.com/minecraft/mc-mods/nbt-autocomplete)

## Поширені NBT-шляхи

### Сутність гравця
- `Health` — Поточне здоров'я (float)
- `foodLevel` — Рівень голоду (int, 0-20)
- `foodSaturationLevel` — Рівень насичення (float)
- `XpLevel` — Рівень досвіду (int)
- `XpP` — Прогрес досвіду (float, 0.0-1.0)
- `Pos[0]`, `Pos[1]`, `Pos[2]` — Координати X, Y, Z
- `Inventory` — Масив інвентарю гравця
- `SelectedItemSlot` — Поточний вибраний слот гарячої панелі (int, 0-8)

### Поширені NBT блоків
- `Items` — Вміст контейнера (скрині, печі тощо)
- `CustomName` — Користувацька назва блоку
- `Lock` — Рядок блокування для контейнерів

### Поширені приклади модифікованих NBT
- **Магічні моди**: часто зберігають ману як `playerMana`, `mana.current` або подібне
- **Технічні моди**: значення енергії на кшталт `energy`, `forgeEnergy` або `energyStorage.energy`
- **RPG-моди**: користувацькі характеристики на кшталт `customStats.strength`, `rpgAttributes.level`

Щоб знайти модифіковані NBT-шляхи, використовуйте `/data get entity @p`, коли мод активний, і шукайте користувацькі теги, додані модом.

## Обмеження

- **Немає доступу до storage на клієнті** — джерело даних storage не підтримується на стороні клієнта (лише на сервері)
- **Продуктивність** — Часте звернення до даних NBT може впливати на продуктивність
- Повертає порожній рядок, якщо шлях недійсний або дані недоступні

## Поради

1. Завжди спершу перевіряйте свої NBT-шляхи в грі за допомогою `/data get`
2. Використовуйте параметр `scale`, щоб перетворювати значення у відсотки або інші зручні формати
3. Пам'ятайте, що деякі дані NBT можуть не синхронізуватися з клієнтом
4. Селектори сутностей обмежені сутностями в межах дистанції промальовування
5. Для модифікованого контенту перевіряйте документацію мода або використовуйте `/data get`, щоб виявити користувацькі NBT-шляхи
