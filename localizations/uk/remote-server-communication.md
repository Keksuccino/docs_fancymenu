# Віддалене серверне з’єднання

Система "Віддалене серверне з’єднання" дає змогу клієнтам FancyMenu взаємодіяти із зовнішніми серверами через WebSocket-з’єднання.

Усі дані є текстовими:

- Підтримується звичайний текст
- Підтримується JSON (як звичайний текст)

Для кожної URL-адреси сервера під час роботи зберігається один кешований **request ID**.
FancyMenu використовує цей ID для відстеження з’єднання та надання його у змінних слухачів.

# Швидкий старт

1. Додайте дію **Підключитися до віддаленого сервера** (необов’язково, але корисно для раннього відкриття з’єднання)
2. Додайте дію **Надіслати дані на віддалений сервер** з тією самою URL-адресою
3. Додайте слухач **Після отримання даних від віддаленого сервера**, щоб реагувати на відповіді
4. Використовуйте **Після підключення до віддаленого сервера** / **Після закриття з’єднання з віддаленим сервером** для логіки стану з’єднання
5. Закривайте з’єднання за потреби за допомогою дій закриття

# Дії

## Підключитися до віддаленого сервера

Ініціалізує з’єднання з віддаленим сервером без надсилання корисних даних.

Вхідні дані:

- URL віддаленого сервера

## Надіслати дані на віддалений сервер

Підключається (або використовує наявне з’єднання) і надсилає текстові дані.

Вхідні дані:

1. URL віддаленого сервера
2. Дані

## Закрити з’єднання з віддаленим сервером

Закриває одне з’єднання за request ID.

Вхідні дані:

- ID запиту з’єднання

## Закрити всі з’єднання з віддаленими серверами

Закриває всі поточні активні з’єднання з віддаленими серверами.

# Слухачі

## Після підключення до віддаленого сервера

Спрацьовує, коли з’єднання з віддаленим сервером ініціалізується.

Змінні:

- `$$request_id`
- `$$remote_server_url`

## Після отримання даних від віддаленого сервера

Спрацьовує, коли дані отримано від підключеного віддаленого сервера.

Змінні:

- `$$request_id`
- `$$remote_server_url`
- `$$data`

## Після закриття з’єднання з віддаленим сервером

Спрацьовує, коли з’єднання з віддаленим сервером закривається.

Змінні:

- `$$request_id`
- `$$remote_server_url`
- `$$intentionally_closed`
- `$$crashed`
- `$$unknown_close_reason`

# Поведінка з’єднання

- З’єднання ініціюються **клієнтом**
- FancyMenu підтримує з’єднання активними у фоновому режимі
- Якщо з’єднання аварійно завершується або виходить із тайм-ауту, FancyMenu повторює спробу кожні 10 секунд
- Коли аварійне з’єднання відновлюється, FancyMenu записує повідомлення про відновлення
- Вихідні ненадіслані повідомлення ставляться в чергу з **максимальним терміном зберігання 30 секунд**
- Повідомлення в черзі, старші за 30 секунд, відкидаються

# Режими URL

- `wss://` = захищене (TLS), рекомендовано
- `ws://` = незашифроване, корисне для локального тестування

Приклад локальної URL-адреси:

- `ws://127.0.0.1:8765`

# Рекомендовані практики

1. Використовуйте одну стабільну URL-адресу для кожного серверного бекенда.
2. Для кожного сценарію використання підтримуйте послідовний формат корисних даних.
3. Обробляйте закриті/аварійно завершені з’єднання через резервну логіку інтерфейсу.
4. Використовуйте дії закриття, коли ваш потік завершено.
5. Використовуйте `wss://` для робочих середовищ.
