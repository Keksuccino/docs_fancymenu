# リモートサーバー通信

「リモートサーバー通信」システムを使うと、FancyMenu クライアントは WebSocket 接続を使用して外部サーバーと通信できます。

すべてのデータはテキストベースです。

- プレーンテキストに対応しています
- JSON にも対応しています（通常のテキストとして扱われます）

各サーバー URL には、実行中に 1 つのキャッシュ済み **リクエスト ID** が割り当てられます。
FancyMenu はこの ID を使用して接続を追跡し、リスナー変数として公開します。

# クイックスタート

1. 接続を早めに開きたい場合は、[**リモートサーバーに接続**](#connect-to-remote-server) を追加します。
2. 同じ URL で [**リモートサーバーにデータを送信**](#send-data-to-remote-server) を追加します。
3. 応答に反応するには [**リモートサーバーからデータ受信時**](#on-remote-server-data-received) を追加します。
4. 接続状態に応じた処理には [**リモートサーバー接続時**](#on-remote-server-connected) と [**リモートサーバー接続終了時**](#on-remote-server-connection-closed) を使用します。
5. 接続を閉じるには [**リモートサーバー接続を閉じる**](#close-remote-server-connection) または [**すべてのリモートサーバー接続を閉じる**](#close-all-remote-server-connections) を使用します。

# アクション

## リモートサーバーに接続

ペイロードデータを送信せずに、リモートサーバー接続を開くか再利用します。

入力:

- リモートサーバー URL

## リモートサーバーにデータを送信

接続し、または既存の接続を再利用して、テキストデータを送信します。

入力:

1. リモートサーバー URL
2. データ

## リモートサーバー接続を閉じる

リクエスト ID によって 1 つの接続を閉じます。

入力:

- 接続リクエスト ID

## すべてのリモートサーバー接続を閉じる

現在アクティブなすべてのリモートサーバー接続を閉じます。

# リスナー

## リモートサーバー接続時

リモートサーバー接続が正常に開いた後にトリガーされます。

変数:

- `$$request_id`
- `$$remote_server_url`

## リモートサーバーからデータ受信時

接続中のリモートサーバーからデータを受信したときにトリガーされます。

変数:

- `$$request_id`
- `$$remote_server_url`
- `$$data`

## リモートサーバー接続終了時

リモートサーバー接続が閉じられたときにトリガーされます。

変数:

- `$$request_id`
- `$$remote_server_url`
- `$$intentionally_closed`
- `$$crashed`
- `$$unknown_close_reason`

# 接続の動作

- 接続は **クライアント起点** です
- FancyMenu はバックグラウンドで接続をアクティブに維持します
- 接続がクラッシュまたはタイムアウトした場合、FancyMenu は 10 秒ごとに再試行します
- クラッシュした接続が復元された場合、FancyMenu は復元メッセージをログに記録します
- 送信されずに残ったメッセージは、**最大 30 秒の有効期限** でキューに入れられます
- 30 秒を超えたキュー済みメッセージは破棄されます

# URL モード

- `wss://` はそのまま使用され、推奨されます。
- `ws://` はそのまま使用され、暗号化されません。
- `https://` は `wss://` に変換されます。
- `http://` は `ws://` に変換されます。
- ホスト名のみの場合は `wss://` が前置されます。
- それ以外の明示的な URL スキームは拒否されます。

明示的な `wss://` URL を推奨します。ローカル URL の例:

- `ws://127.0.0.1:8765`

サービスごとに 1 つの安定した URL を使用し、閉じられた/クラッシュしたリスナー状態を処理し、不要になった接続は閉じてください。
