# ตัวยึด NBT Data

FancyMenu มีตัวยึด NBT อยู่ 2 แบบ:

| ตัวยึด | ทำงานฝั่ง | ข้อมูลที่ใช้ได้ |
|---|---|---|
| `nbt_data_get` | ไคลเอนต์ | เอนทิตีและบล็อกเอนทิตีที่มองเห็นได้ฝั่งไคลเอนต์ |
| `nbt_data_get_server` | เซิร์ฟเวอร์ | เป้าหมายของคำสั่ง `/data get` แบบวานิลลา; ต้องมี FancyMenu บนเซิร์ฟเวอร์ |

# ตัวยึดฝั่งไคลเอนต์

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health"}}
```

## ค่า

| ค่า | จำเป็น | คำอธิบาย |
|---|---|---|
| `source_type` | ใช่ | `entity` หรือ `block` |
| `entity_selector` | สำหรับเอนทิตี | ตัวเลือกฝั่งไคลเอนต์, UUID, หรือชื่อเอนทิตีที่ตรงกันแบบเป๊ะ |
| `block_pos` | สำหรับบล็อก | พิกัดจำนวนเต็มแบบสัมบูรณ์ 3 ค่า เช่น `100 64 -200` |
| `nbt_path` | ใช่ | เส้นทาง NBT เช่น `Health`, `Pos[0]`, หรือ `Inventory[0].id` |
| `scale` | ไม่ | คูณผลลัพธ์ `value` ที่เป็นตัวเลข; ค่าเริ่มต้น `1.0` |
| `return_type` | ไม่ | `value`, `string`, `snbt`, หรือ `json`; ค่าเริ่มต้น `value` |

พิกัดบล็อกฝั่งไคลเอนต์ไม่รองรับพิกัด `~` หรือ `^`.

## ตัวเลือกตัวเลือกเอนทิตีฝั่งไคลเอนต์

| ตัวเลือก | เป้าหมายเริ่มต้น | ลำดับเริ่มต้น |
|---|---|---|
| `@s` | ผู้เล่นท้องถิ่น | ตัวเอง |
| `@p` | ผู้เล่น | ใกล้ที่สุด |
| `@a` | ผู้เล่น | ลำดับการวนของไคลเอนต์ |
| `@r` | ผู้เล่น | แบบสุ่ม |
| `@e` | เอนทิตีทั้งหมดที่มองเห็นได้ฝั่งไคลเอนต์ | ลำดับการวนของไคลเอนต์ |

`@e` จะไม่เลือกเอนทิตีที่ใกล้ที่สุด เว้นแต่คุณจะเพิ่ม `sort=nearest` การค้นหาด้วย UUID โดยตรงและชื่อเอนทิตีที่ตรงกันแบบเป๊ะก็รองรับเช่นกัน

รองรับตัวเลือกของตัวเลือกดังนี้:

| ตัวเลือก | คำอธิบาย |
|---|---|
| `type` | รหัสเอนทิตี; ใส่ `!` นำหน้าเพื่อยกเว้น |
| `name` | ชื่อที่แสดงแบบตรงกันเป๊ะ; ใส่ `!` นำหน้าเพื่อยกเว้น |
| `tag` | แท็กของเอนทิตี; ใส่ `!` นำหน้าเพื่อยกเว้น |
| `limit` | จำกัดผลลัพธ์เป็นจำนวนบวก |
| `sort` | `nearest`, `furthest`, `random`, หรือ `arbitrary` |
| `distance` | ช่วงระยะทางแบบวานิลลา เช่น `..10` หรือ `5..20` |
| `x`, `y`, `z` | จุดเริ่มต้นของการค้นหา; รับค่าระดับสัมบูรณ์และออฟเซ็ต `~` |
| `dx`, `dy`, `dz` | ขนาดกล่องค้นหาจากจุดเริ่มต้น |

พิกัดท้องถิ่น `^` และตัวเลือกตัวเลือกแบบวานิลลาอื่น ๆ ไม่รองรับโดยตัวยึดฝั่งไคลเอนต์

ตัวอย่าง:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@e[type=minecraft:zombie,sort=nearest,limit=1,distance=..20]","nbt_path":"Health"}}
```

## ประเภทการคืนค่า

| ประเภท | ผลลัพธ์ |
|---|---|
| `value` | แท็กตัวเลขจะถูกจัดรูปแบบเป็นตัวเลขและใช้ `scale`; แท็กสตริงจะคืนค่าเป็นข้อความ; แท็กอื่น ๆ จะคืนค่าเป็นข้อความลักษณะ SNBT |
| `string` | คืนค่าข้อความของแท็ก หรือสตริงว่างเมื่อแท็กไม่มีค่าที่เป็นสตริง |
| `snbt` | คืนค่าการแทนข้อมูลแบบ SNBT ของแท็ก |
| `json` | สำหรับแท็กชนิด compound เท่านั้น: คืนค่าคอมโพเนนต์ข้อความ Minecraft ที่ถูกซีเรียลไลซ์ ซึ่งมีผลลัพธ์ NBT แบบจัดรูปแบบสวยงาม |

โหมด `json` ฝั่งไคลเอนต์ไม่ใช่การแปลง NBT เป็น JSON โดยตรง

## ตัวอย่าง

ความหิวของผู้เล่น:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"foodLevel"}}
```

ไอดีของไอเท็มช่องแรกในแถบลัด:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Inventory[{Slot:0b}].id","return_type":"string"}}
```

จำนวนไอเท็มของบล็อกเอนทิตี:

```text
{"placeholder":"nbt_data_get","values":{"source_type":"block","block_pos":"100 64 -200","nbt_path":"Items[0].count"}}
```

# ตัวยึดฝั่งเซิร์ฟเวอร์

`nbt_data_get_server` ทำงานตามพฤติกรรม `/data get` ของเซิร์ฟเวอร์ และรองรับ:

- ตัวเลือกเอนทิตีฝั่งเซิร์ฟเวอร์แบบเต็มรูปแบบ
- เป้าหมายบล็อกด้วยพิกัดแบบสัมบูรณ์, แบบสัมพัทธ์ (`~`), หรือแบบท้องถิ่น (`^`)
- สตอเรจของคำสั่งผ่าน `source_type:"storage"`

```text
{"placeholder":"nbt_data_get_server","values":{"source_type":"entity","entity_selector":"@s","nbt_path":"Health","return_type":"value"}}
```

ตัวยึดจะคืนค่าว่างจนกว่าคำตอบจากเซิร์ฟเวอร์จะมาถึง คำตอบจะถูกแคชไว้ช่วงสั้น ๆ เพื่อหลีกเลี่ยงการร้องขอบ่อยเกินไป

# การหาเส้นทาง NBT

ใช้คำสั่งที่ตรงกันโดยไม่ระบุเส้นทาง NBT เพื่อดูข้อมูลที่มี:

```text
/data get entity @s
/data get block 100 64 -200
```

ผลลัพธ์ฝั่งไคลเอนต์จำกัดเฉพาะข้อมูลที่ซิงก์มายังไคลเอนต์แล้ว เป้าหมายหรือเส้นทางที่ไม่ถูกต้องจะคืนค่าสตริงว่าง และเขียนรายละเอียดลงใน `logs/latest.log`
